## 这是什么

GAIA Desktop 对 GS1 数据做三件事：

- **解析** — 输入、粘贴、打开或扫描一条 GS1 元素串或 Digital Link URI，并以完整报告的形式阅读
  结果：每个应用标识符（AI）表示什么、哪里有问题、为什么有问题；
- **构建** — 把 AI／值对组装成元素串或 Digital Link URI；
- **合并** — 把同一标签上最多三个 GS1-128 条码合并成一个 GS1 DataMatrix 会承载的
  单一元素串，作为整体校验，并绘制符号。

本应用关于 GS1 的全部知识 —— 每一条 AI 定义、每一条校验规则、每一条错误消息、每一段本地化说明
—— 都来自底层的 GAIA 引擎。应用本身不添加任何规则：它接受的内容与引擎接受的完全一致。

## 运行

```bash
java -jar gaia-desktop.jar
```

该 JAR 文件需要与它一同发布的 `lib/` 目录 —— 请把两者放在一起，否则应用无法启动。（也可以构建
一个自包含的 JAR 文件；参见[开发者指南](../../GaiaDesktop-Developer.md#packaging)。）

必须安装 **Java 21 或更高版本**。发布包针对特定的操作系统和处理器架构，请使用为您的机器构建的
JAR 文件。

若要以指定语言打开应用，同时不改变已保存的语言：

```bash
java -jar gaia-desktop.jar --language=FR
```

取值可以是目录代码（`FR`、`PCM`、`ARZ`）、完整名称（`FRENCH`、`WU-CHINESE`），也可以是语言标签
（`fr`；粤语用 `zh-HK`，埃及阿拉伯语用 `ar-EG`）—— 不区分大小写。该设置只对本次运行有效：您保存
的语言不受影响，因此为同事创建的快捷方式不会改变您自己这份副本启动时使用的语言。而在应用*内部*
选择语言则是一次真正的选择，会照常保存。若取值不指向任何语言，程序会在控制台记录一条提示并忽略
它，然后以保存的语言打开，而不是拒绝启动。

启动时，控制台会打印一行内容，写明应用版本、构建日期和引擎版本。提交缺陷报告时，请引用这一行。

## 解析模式

### 输入栏与 {GS} 标记

输入栏接受元素串、GS1 Digital Link URI，或带 AIM Code ID 前缀（`]d2…`）的原始扫描数据。
按 <kbd>Enter</kbd> 开始解析。

可变长度的 AI 之间以 **FNC1** 分隔 —— 那是不可见的控制字符 `0x1D`。文本框无法保存该字符：它会被
悄悄丢弃，于是 `01…` + FNC1 + `10LOT` 会变成 `01…10LOT`，一条含义完全不同的元素串。

因此应用把分隔符显示为可见的标记 **`{GS}`**，并在送往解析器的途中还原回去：

- **`{GS}` 按钮**在光标处插入该标记；
- **粘贴**真正的分隔符字符时 —— 无论用键盘、右键菜单还是拖放 —— 都会自动转换成 `{GS}`，不会丢失
  任何内容；
- 该标记的写法与报告中的写法完全一致，因此从报告里复制的值可以直接粘贴回来。

采集记录、报告和保存的历史中保存的都是**真正的**分隔符。标记只是您所看到和输入的形式。

### 扫描

> **仅限 Windows。** Zebra 只为 Windows 提供扫描器驱动，因此在 macOS 和 Linux 上，应用根本不会
> 创建任何扫描器控件 —— 没有*连接扫描器*开关，没有设备选择，没有*扫描器*菜单，状态栏里也没有
> 扫描器状态。它们不是被置灰，而是压根不存在，因为没有任何设置或设备能够启用它。其余功能，包括
> 打开保存了扫描数据的文件，在所有平台上都可用。

*连接扫描器*会打开选择框中指定的设备；默认值 `ZebraAllScanners` 适用于大多数型号。每次扫描都会
被解析并自动追加到历史中。

扫描器数据按字节读取，因此 AIM Code ID 前缀和每一个 FNC1 分隔符都会原样送达解析器。

在构建模式下扫描器控件被隐藏，但已连接的扫描器仍在工作：*扫描器 → 连接／断开*
（<kbd>⌘K</kbd>）依然可以切换它，状态栏依然会报告它，编辑器打开时收到的扫描同样会被采集。 在合并模式下，这些控件保持可见，每次扫描都加入合并，而不是历史。

首次设置扫描器——Zebra Scanner SDK、扫描器的 USB 模式和 GS1 设置——在
[Zebra 扫描器设置指南](GaiaDesktop-Zebra-Scanner-Windows-Chinese.md)中有分步说明，该指南随每个 zip 包放在 `docs/` 下。 如果设备无法连接，请参阅[疑难解答](#疑难解答)。

### 打开文件

*文件 → 打开文本文件…* 会把**每一非空行都当作一条独立的采集记录**来解析，这是处理别人发来的一批
扫描数据的快捷方式。文件按字节读取，因此其中的原始分隔符会被保留。

### 采集记录历史

最新的排在最前。每一行显示一个有效／无效的圆点、一行摘要，以及采集时间、来源和其中包含的 AI
数量。日期只出现在往日的记录上；当天的行只显示时间。

对 Digital Link 而言摘要是 **Digital Link URI**，其余情况下是 **HRI**：对元素串来说，
`(01)09506000134352 (17)261231` 比 `01095060001343521726123110…` 更易读。

右键点击某条采集记录，可以复制它的输入或 HRI、把它送回输入栏、在编辑器中打开、删除它，或清空
历史。

## 构建模式

### AI 编辑器

一张 AI／值对的表格。您可以直接输入 AI 代码，也可以在*添加 AI…* 列表中从**引擎已知的全部 AI**
中选择；**标题**、**格式**和**描述**三列会随着输入自动填充，并使用您选择的语言。该列表不会提供
构建时会被拒绝的 AI。

表格末尾始终保留**一个空行**：在其中输入内容，下一行便会出现，因此包含多个 AI 的串从不需要
*添加行*。

编辑行为符合表格应有的习惯：<kbd>Enter</kbd>、<kbd>Tab</kbd>、<kbd>Shift</kbd>+<kbd>Tab</kbd>
以及点击别处都会**保留**您输入的内容；<kbd>Esc</kbd> 则会放弃。<kbd>Tab</kbd> 依次从 AI 移到值，
再移到下一行，并跳过不可编辑的列。

### 编辑器会拒绝什么

| | 会发生什么 |
|---|---|
| 引擎无法识别的 AI | 输入过程中该行即变红；构建被拒绝，并给出说明 |
| 从列表中重复添加同一个 AI | 不会添加 —— 消息会指出它，并选中已包含该 AI 的那一行 |
| 手工输入了重复的同一个 AI | 两行都会被标记；构建以错误 `GE-S004` 被拒绝 |
| 没有可构建的内容 | 给出一条消息；不创建任何采集记录 |

同一个 AI 在一条元素串中只能出现一次，因此列表会当场拒绝，而不是让您去尝试一次注定失败的构建。

### 元素串还是 Digital Link

**构建元素串**会把各行组装起来，并在标准要求的位置插入 FNC1 分隔符。**构建 Digital Link** 生成
一个 URI；展开 *Digital Link 目标*，即可把它指向您自己的解析服务，而不是标准的 `id.gs1.org`：

| 字段 | 作用 | 留空表示 |
|---|---|---|
| 域名 | 解析服务的主机，例如 `example.com` | `id.gs1.org` |
| 路径前缀 | AI 路径之前的一段，例如 `/products` | 无前缀 |

**成功**时，结果的表现与一次扫描完全相同：被解析、加入历史、渲染成报告并保存。构建过程通过解析
自身的输出来校验，因此它返回的内容必定有效。

**失败**时不会产生任何采集记录。原因会留在构建按钮下方，每个问题一行，分别给出错误、所属的 AI
以及引擎自己的说明：

```
GE-C003  (01)  Check digit validation failed for AI (01) value ''09506000134350''
```

> 该消息中成对重复的引号来自引擎的错误目录，而不是本应用。

### 编辑已有的采集记录

右键点击一条采集记录 → **构建**，即可把其中的 AI 载入编辑器。修改某个值后重新构建，结果会作为一条
新的采集记录出现 —— 原记录保持不变。

## 合并模式

较旧的标签常常把数据分散在**多个 GS1-128 条码**上——一个放 GTIN，另一个放有效期和批号——因为
单个线性条码装不下全部内容。合并最多接收**三个**这样的条码，把它们合并成一个
**GS1 DataMatrix** 会承载的单一元素串，并作为整体进行校验。结果有效后，应用会绘制 DataMatrix
符号。

这些条码都不必各自完整。缺少 GTIN 的批号单独校验时会以 `GE-S005` 失败，但对一组条码中的一个来说
这很正常，所以合并改为在合并结果上校验它。

### 合并栏

切换到**合并**后，输入栏会被窗口底部的一条栏取代。采集记录历史让到一旁，因为
合并模式的扫描不是采集记录，也从不进入历史。报告区改为显示合并报告：

```
┌────────────────────────────────────────────────────────────────────┐
│ [Parse|Build|Combine]   (scanner controls, on Windows)   Options   │
├────────────────────────────────────────────────────────────────────┤
│ Combine report                                   │ Options panel   │
├────────────────────────────────────────────────────────────────────┤
│ [Reset] [Remove Last] │ Barcode: [ …………………………………………… ] [Add]       │
├────────────────────────────────────────────────────────────────────┤
│ 2 of 3 GS1-128 barcodes                                   [About]  │
└────────────────────────────────────────────────────────────────────┘
```

条码有两种输入方式：

- **扫描。** 在 Windows 上，合并模式下扫描器控件仍留在工具栏中，每次扫描直接进入
  合并，而不是历史。
- **键入或粘贴**到 *条码* 栏，然后按 <kbd>Enter</kbd> 或
  **添加**。FNC1 写作 **`{GS}`**，与输入栏相同。键入时不带 AIM Code ID 的条码按
  GS1-128 处理。

| 按钮 | 作用 |
|---|---|
| **添加** | 添加栏中的条码 |
| **移除最后一个** | 移除最近添加的条码（没有条码时不可用） |
| **重置** | 移除所有条码，清空输入栏和任何拒收提示，重新开始 |

状态栏始终显示已持有多少个条码（*GS1-128 条码 2/3*），或说明上一个条码为何被拒收。

### 合并会拒收什么

被拒收的条码不会被添加。报告和状态栏都会说明原因：

| 条码 | 拒收原因 |
|---|---|
| 空的输入栏 | 没有可添加的内容 |
| 第四个条码 | 一个标签最多由三个条码合并而成。请移除最后一个，或重置 |
| 按 AIM Code ID 判断为其他码制 | 只合并 GS1-128，因此 GS1 DataMatrix（`]d2`）或 QR Code 会被拒收，并给出其名称 |
| 无法读取的 AI | 语法错误；显示引擎的错误代码和消息 |
| 完全没有 AI | 没有可合并的内容 |
| 已扫描过的条码 | 同一元素串出现两次，例如同一条码又扫了一遍；报告会说明它重复了之前的哪个条码 |

合并只拒收完全无法使用的条码。其他一切（错误的校验位、无效的日期、缺少的配套 AI）
都会被接受，并在合并结果上评判。

### 重复与冲突

AI 按扫描顺序合并。当两个条码带有相同的 AI 时：

- **值相同**：只保留一次，列在 *重复——保留一次* 下，并注明读到它的条码；
- **值不同**：这就是**冲突**。结论显示 *冲突*，相互矛盾的值按条码逐一列出，
  在冲突解决之前**不合并任何内容**。请移除有问题的条码，或重置。

### 合并报告

从上到下：

1. **结论**：*无扫描*、*冲突*、有效或无效，以及持有的条码数量。
2. **扫描**：每个条码的原始内容、码制，以及去掉 AIM Code ID 后剩下的元素串。只有合并结果才能
   定夺的问题会标在该条码上，并注明 *按合并结果判定*。
3. **重复**和**冲突**（如果有）。
4. **合并结果**：元素串、其 HRI 和长度，然后是以带标注的纸带形式显示的合并输入，
   以及每个 AI 一张卡片，排版与[解析报告](#报告)相同。之后，合并结果上的每个错误和警告都列在
   *校验* 下。
5. **GS1 DataMatrix 符号**，下方附有 HRI。只有合并结果有效时才会绘制。否则报告会说明未绘制的
   原因，以免误打印无效的符号。

例如，一个带两个条码的标签：

| 条码 | 内容 | 单独校验 |
|---|---|---|
| `]C10109506000134352` | (01) GTIN | 有效 |
| `]C11726123110LOT-ABC` | (17) 有效期、(10) 批号 | 两个 AI 都报 `GE-S005`，按合并结果判定 |

它们合并为 `01095060001343521726123110LOT-ABC`，HRI 为
`(01)09506000134352 (17)261231 (10)LOT-ABC`，结果有效，因此会绘制符号。AI `17` 是定长的，
所以其后不需要 FNC1。合并会在标准要求的每个位置插入 FNC1。

只要持有一个条码，**保存报告** 就能像导出解析报告一样把合并报告导出为 HTML 或 PDF
（参见[导出](#导出)）。HTML 文件名以 `gaia-combine-` 开头。

报告跟随所选的语言和主题。更改解析选项或语言会重新校验已持有的条码。切换到解析或
构建再切回来，这些条码依然保留，但重启后不会保留：合并模式的条码不会被保存。

## 报告

选中的采集记录会以完整报告的形式呈现：结论横幅、拆解为带标签“纸带”的元素串、解析元数据、每个 AI
一张附带解释的卡片，以及带修正指引的错误与警告。

对于 **Digital Link**，每张 AI 卡片还会标出它的结构角色 —— **主键**、**键限定符**或**数据属性**
—— 并按它们在 URI 中出现的顺序用颜色区分。角色只在 Digital Link 中显示：在普通元素串里，AI 并没有
可供描述的 URI 位置。

报告会跟随您选择的语言和主题。

### 导出

| | |
|---|---|
| **保存报告 → 另存为 HTML…**（<kbd>⌘S</kbd>） | 原样写出屏幕上的内容：一个自包含文件，可在任何浏览器中打开 |
| **保存报告 → 另存为 PDF…**（<kbd>⌘P</kbd>） | 通过系统打印对话框打印报告 —— 请在其中选择 PDF 目标 |

PDF 之所以走打印对话框，是因为目标和文件名都在那里选择：macOS 上选 **PDF ▾ → 存储为 PDF**，
Windows 上选 **Microsoft Print to PDF**，Linux 上选**打印到文件**。页面会正确分页，文字仍可选中。

打印和 PDF 输出始终使用浅色配色，即使应用处于深色主题，并且保留彩色的 AI 标签和结论横幅。

如果您的机器完全没有配置打印机或 PDF 目标，应用会予以说明，并引导您使用 HTML 导出 —— 它可以在
任何浏览器中打印。

## 解析选项

右侧面板汇集了引擎的全部选项。改动其中任何一项都会**立即重新解析选中的采集记录**，因此该面板也
可以用来回答“换成这些设置，这条输入会是什么样”，而不只是影响下一次扫描。

| 选项 | 取值 |
|---|---|
| 解析模式 | `SYNTAX`、`CONTENT`、`DATA_CARRIER`、`INTERPRETATION` —— 解析要深入到哪一步 |
| 语言 | 35 套消息目录 |
| 顺序 | `LITTLE`（dd/mm/yyyy）、`MIDDLE`（mm/dd/yyyy）、`BIG`（yyyy/mm/dd） |
| 分隔符 | `SLASH`、`HYPHEN`、`PERIOD` |
| 月 | `TWO_DIGIT`（12）、`THREE_LETTER`（DEC） |
| 年 | `FOUR_DIGIT`（2026）、`TWO_DIGIT`（26） |
| 跳过“requires”检查 | 不再因缺少必需的伴随 AI 而拒绝（`GE-S005`） |
| 跳过“excludes”检查 | 不再拒绝标准所禁止的 AI 组合（`GE-S006`） |

面板底部的*恢复默认设置*会还原引擎自身的默认值。

### 首次启动

在尚未保存任何设置时，应用会从**您机器的区域设置**中取值，而不是采用引擎的默认值：

- **语言**取自系统区域设置；若没有对应的目录，则回退到英语；
- **日期选项**依据您区域设置中的短日期格式推断：各部分的顺序、分隔符，以及月和年是否使用缩写。

> **注意。** 因此，短日期使用两位年份的区域设置在这里也会以两位年份开始：这与系统其他部分一致，
> 但不同于引擎自身四位年份的默认值。在面板中改动后，该选择就会保留。

## 语言

选择语言会改变**整个应用程序** —— 菜单、按钮、编辑器、选项面板、状态行和报告 —— 而不只是错误
消息。从右往左书写的语言会把窗口和报告整体镜像。

全部 35 种语言均可使用，覆盖分为两层：

| | 覆盖范围 |
|---|---|
| 解析报告和引擎的全部错误消息 | **全部 35 种语言** |
| 应用自身的菜单、按钮和标签 | **全部 35 种语言** |

从右往左书写的语言 —— 阿拉伯语、埃及阿拉伯语、波斯语和乌尔都语 —— 自应用打开的那一刻起就会镜像
窗口和报告。

语言会在多次运行之间被记住。若只想临时用另一种语言打开一次，请参阅
[`--language`](#运行)。

有几处内容在所有语言中都刻意不作翻译：原始值旁边打印的简短字段名（`format`、`position`、`raw`、
`len` 等），它们是标识符而非词语；示例名称和码制名称，它们是 GS1 与行业术语；以及一段较长的标准
原文 —— 在那里半吊子的翻译反而会误导读者。

## 哪些内容会被记住

您主目录中 `.gaia-desktop` 下的两个文件：

| 文件 | 内容 |
|---|---|
| `options.properties` | 全部解析选项、主题、选项面板是否打开、最后使用的扫描器、窗口关闭时所处的模式，以及更新检查的设置——是否开启、上次运行时间，以及您选择跳过的版本 |
| `captures.tsv` | 采集记录历史，最新的在前，上限 500 条 |

选项在您每次修改时写入；历史在其发生变化时写入。两者都会在退出时再次写入。

删除其中任一文件只会重置对应的部分，不会影响其他内容 —— 它们被分开保存，正是为了让损坏的历史不至
于让您丢失设置。手工编辑弄坏的文件同样不是灾难：每项设置会各自回退到默认值，因此一行错误只影响
那一行。

历史保存的是输入，而不是解析结果。加载时会重新解析，也就是说恢复出来的采集记录反映的是**当前**
生效的选项，而不是采集当时的选项。

合并模式中持有的条码不会被保存：重启后合并从空白开始。

| | |
|---|---|

## 疑难解答

| 现象 | 原因与解决办法 |
|---|---|
| 应用无法启动，或报告 `NoClassDefFoundError` | `lib/` 目录必须与 JAR 文件放在一起。请勿分开，或改用自包含的发布包 |
| 启动时控制台出现 *“Unsupported JavaFX configuration…”* | 属正常且无害 —— 工具包只是记录自己是如何被加载的。应用运行正常 |
| 粘贴的分隔符似乎消失了 | 这是预期行为：它被改写成可见标记 `{GS}`，解析器收到的仍是真正的字符。参见 [{GS} 标记](#输入栏与-gs-标记) |
| 找不到*连接扫描器*按钮 | 您正在使用 macOS 或 Linux，那里没有扫描器驱动。参见[扫描](#扫描) |
| 扫描器连不上 | 请检查选择框中的逻辑名称是否与您的型号相符、扫描器是否已连接，以及是否有其他程序正在占用它。[Zebra 扫描器设置指南](GaiaDesktop-Zebra-Scanner-Windows-Chinese.md#11-故障排除)列出了每个错误代码。 |
| 导出 PDF 时提示没有目标 | 您的机器没有配置打印机或 PDF 目标。请添加一个，或先导出 HTML 再从浏览器打印 |
| 菜单项显示出类似 `act.hri` 的内容 | 缺少标签 —— 请报告该问题；这是构建阶段的缺陷，而不是某项设置 |

## 限制

- **扫描仅限 Windows**，因为驱动只有 Windows 版。
- **PDF 走的是打印对话框**，而不是保存对话框。
- **Digital Link 目标只接受域名和路径前缀**，不支持额外的查询参数或片段。
- **同一个 AI 在一条元素串中只能出现一次** —— 这是 GS1 的规则，而非本应用的限制。
- **合并只接受 GS1-128 条码，最多三个**，并且不会在两次运行之间保留它们。
