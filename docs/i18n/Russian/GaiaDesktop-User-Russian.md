## Что это такое

GAIA Desktop делает с данными GS1 три вещи:

- **Анализирует** — наберите, вставьте, откройте или отсканируйте строку элементов GS1 либо
  URI Digital Link и прочитайте результат как полный отчёт: что означает каждый идентификатор
  применения (AI), что в нём не так и почему;
- **Собирает** — соединяет пары «AI / значение» в строку элементов или в URI Digital Link;
- **Объединение** — объединяет до трёх штрихкодов GS1-128 с одной этикетки в одну строку
  элементов, которую нёс бы GS1 DataMatrix, проверяет её целиком и рисует символ.

Всё, что приложение знает о GS1 — каждое определение AI, каждое правило проверки, каждое
сообщение об ошибке и каждое локализованное описание — берётся из лежащего в основе движка
GAIA. Приложение не добавляет собственных правил: оно принимает ровно то, что принимает движок.

## Запуск

```bash
java -jar gaia-desktop.jar
```

JAR-файлу нужен каталог `lib/`, который поставляется рядом с ним, — держите их вместе, иначе
приложение не запустится. (Можно собрать и один самодостаточный JAR-файл; см.
[руководство разработчика](../../GaiaDesktop-Developer.md#packaging).)

Требуется установленная **Java 21 или новее**. Сборка привязана к одной операционной системе и
одной архитектуре процессора — используйте JAR-файл, собранный для вашей машины.

Чтобы открыть приложение на определённом языке, не меняя сохранённый язык:

```bash
java -jar gaia-desktop.jar --language=FR
```

Значением может быть код каталога (`FR`, `PCM`, `ARZ`), полное имя (`FRENCH`, `WU-CHINESE`) или
языковой тег (`fr`, `zh-HK` для кантонского, `ar-EG` для египетского арабского) — регистр не
важен. Указание действует только для этого запуска: сохранённый язык остаётся нетронутым, так
что ярлык, сделанный для коллеги, не изменит язык, на котором открывается ваша собственная
копия. Выбор языка *внутри* приложения — это уже настоящий выбор, и он сохраняется как обычно.
Значение, не обозначающее ни одного языка, игнорируется с записью в консоли: приложение
откроется на сохранённом языке, а не откажется запускаться.

При запуске консоль печатает строку с версией приложения, датой сборки и версией движка. Именно
её стоит приводить в сообщении об ошибке.

## Окно

```
┌────────────────────────────────────────────────────────────────────┐
│ menu bar                                                           │
├────────────────────────────────────────────────────────────────────┤
│ [Parse|Build|Combine]  … mode-specific controls …  Save   Options  │
├────────────────────────────────────────────────────────────────────┤
│ input bar (Parse)   or   AI editor (Build)                         │
├──────────────────┬─────────────────────────────────────────────────┤
│ Captures         │ Parse report                    │ Options       │
│ (newest first)   │                                 │ panel         │
├──────────────────┴─────────────────────────────────────────────────┤
│ status …                                     scanner: off  [About] │
└────────────────────────────────────────────────────────────────────┘
```

> Схема сохраняет английские подписи, как и все блоки кода в этой документации. На экране вы
> увидите *Анализ* / *Сборка* / *Объединение*, *Захваты*, *Сохранить отчёт*, *Параметры*, *сканер: выкл.* и
> *О программе*.

**В macOS и Linux строки со сканером на этой схеме нет** — ни переключателя, ни выбора
устройства на панели инструментов, нет меню *Сканер*, нет *сканер: выкл.* в строке состояния.
См. [Сканирование](#сканирование).

Переключатель **Анализ ⇄ Сборка** меняет только полосу под панелью инструментов и элементы
управления захватом. История, отчёт, панель параметров и команды экспорта служат обоим режимам,
потому что удачная сборка просто становится ещё одним захватом. Режим **Объединение** устроен иначе: см. [Режим «Объединение»](#режим-объединение).

Панель параметров **при первом запуске закрыта**. Режим, видимость панели, тема и последний
использованный сканер запоминаются между запусками.

**Новые версии.** Через несколько секунд после запуска, не чаще раза в день, приложение
спрашивает у GitHub, не вышла ли более новая версия GAIA Desktop. Если вышла, в строке состояния
появляется ссылка — *Доступна версия GAIA Desktop 1.1.0* — которая открывает страницу выпуска в вашем
браузере; ничего не скачивается и не устанавливается за вас. *Пропустить эту версию* скрывает
уведомление до следующего выпуска. Проверка молчит, когда нового ничего нет или GitHub
недоступен. *Справка → Проверить обновления…* проверяет сразу и сообщает результат;
*Справка → Проверять обновления автоматически* выключает и снова включает ежедневную проверку.

## Режим «Анализ»

### Строка ввода и токен {GS}

Строка принимает строку элементов, URI GS1 Digital Link или необработанный результат
сканирования вместе с префиксом AIM Code ID (`]d2…`). <kbd>Enter</kbd> запускает анализ.

AI переменной длины разделяются символом **FNC1** — невидимым управляющим символом `0x1D`.
Текстовое поле не может его хранить: он будет молча удалён, и `01…` + FNC1 + `10LOT` придёт как
`01…10LOT` — строка элементов с другим смыслом.

Поэтому приложение показывает разделитель как видимый токен **`{GS}`** и превращает его обратно
по пути к анализатору:

- **кнопка `{GS}`** вставляет токен там, где стоит курсор;
- **вставка** настоящих символов-разделителей — с клавиатуры, из контекстного меню или
  перетаскиванием — автоматически превращает их в `{GS}`, так что ничего не теряется;
- токен записывается ровно так, как его записывает отчёт, поэтому значение, скопированное из
  отчёта, можно вставить обратно без изменений.

Захват, отчёт и сохранённая история содержат **настоящий** разделитель. Токен — это только то,
что вы видите и набираете.

### Сканирование

> **Только Windows.** Zebra поставляет драйверы сканера исключительно для Windows, поэтому в
> macOS и Linux приложение вообще не создаёт элементов управления сканером — ни переключателя
> *Подключить сканер*, ни выбора устройства, ни меню *Сканер*, ни состояния сканера в строке
> состояния. Ничего не «затенено», потому что нет ни настройки, ни устройства, которые могли бы
> это включить. Всё остальное, включая открытие файла с сохранёнными сканами, работает везде.

*Подключить сканер* открывает устройство, указанное в списке; `ZebraAllScanners` — значение по
умолчанию, подходящее для большинства моделей. Каждый скан анализируется и автоматически
добавляется в историю.

Данные сканера читаются побайтно, поэтому префикс AIM Code ID и каждый разделитель FNC1
доходят до анализатора ровно в том виде, в каком их отправил сканер.

В режиме «Сборка» элементы управления сканером скрыты, но подключённый сканер продолжает
работать: *Сканер → Подключить / Отключить* (<kbd>⌘K</kbd>) по-прежнему его переключает, строка
состояния по-прежнему о нём сообщает, а скан, пришедший при открытом редакторе, всё равно будет
захвачен. В режиме «Объединение» элементы управления остаются, и каждый скан добавляется к
объединению, а не в историю.

Первая настройка сканера — Zebra Scanner SDK, режим USB сканера и параметры GS1 — пошагово
описана в [руководстве по настройке сканера Zebra](GaiaDesktop-Zebra-Scanner-Windows-Russian.md), которое входит в каждый zip в
папке `docs/`. Если устройство не подключается, см. [Устранение неполадок](#устранение-неполадок).

### Открытие файла

*Файл → Открыть текстовый файл…* анализирует **каждую непустую строку как отдельный захват** —
это быстрый способ обработать партию сканов, которую вам прислали. Файл читается побайтно,
поэтому находящиеся в нём настоящие разделители сохраняются.

### История захватов

Новые сверху. В каждой строке — точка «годно / не годно», однострочная сводка, а также время
захвата, источник и число AI. Дата появляется только у захватов предыдущих дней; у сегодняшних
строк показано лишь время.

Сводка — это **URI Digital Link** для Digital Link и **HRI** во всех остальных случаях: для
строки элементов `(01)09506000134352 (17)261231` читается лучше, чем
`01095060001343521726123110…`.

Щёлкните захват правой кнопкой, чтобы скопировать его ввод или HRI, вернуть его в строку ввода,
открыть в редакторе, удалить или очистить историю.

## Режим «Сборка»

### Редактор AI

Таблица пар «AI / значение». Наберите код AI или выберите из **всех AI, которые знает движок**,
в списке *Добавить AI…*; столбцы **Название**, **Формат** и **Описание** заполняются по мере
набора, на выбранном языке. Список не предложит AI, который сборка отвергла бы.

В конце таблицы всегда остаётся **одна пустая строка**: наберите в ней что-нибудь, и появится
следующая, так что строке с несколькими AI никогда не нужна команда *Добавить строку*.

Правка ведёт себя так, как и должна вести себя таблица: <kbd>Enter</kbd>, <kbd>Tab</kbd>,
<kbd>Shift</kbd>+<kbd>Tab</kbd> и щелчок в стороне **сохраняют** набранное; <kbd>Esc</kbd>
отменяет. <kbd>Tab</kbd> переходит от AI к Значению и дальше к следующей строке, пропуская
столбцы, которые нельзя править.

### Что редактор отклоняет

| | Что происходит |
|---|---|
| AI, который движок не распознаёт | Строка краснеет прямо во время набора; сборка отклоняется с пояснением |
| Тот же AI второй раз, из списка | Не добавляется — сообщение называет его, а строка, где он уже есть, выделяется |
| Тот же AI второй раз, набранный вручную | Помечаются обе строки; сборка отклоняется с ошибкой `GE-S004` |
| Собирать нечего | Сообщение; захват не создаётся |

В одной строке элементов AI может встречаться лишь однажды — поэтому список отказывает сразу, а
не позволяет предпринять заведомо обречённую сборку.

### Строка элементов или Digital Link

**Собрать строку элементов** соединяет строки, вставляя разделитель FNC1 всюду, где этого
требует стандарт. **Собрать Digital Link** выдаёт URI; разверните *Цель Digital Link*, чтобы
направить его на ваш собственный резолвер вместо канонического `id.gs1.org`:

| Поле | Действие | Пустое значение |
|---|---|---|
| Домен | Узел резолвера, например `example.com` | `id.gs1.org` |
| Префикс пути | Сегмент перед путём AI, например `/products` | без префикса |

При **успехе** результат ведёт себя точно так же, как скан: он разбирается, добавляется в
историю, отображается как отчёт и сохраняется. Сборка проверяет себя, разбирая собственный
вывод, поэтому всё, что она возвращает, заведомо корректно.

При **неудаче** ничего не захватывается. Причина остаётся под кнопками сборки — по строке на
каждую проблему, в каждой указаны ошибка, относящийся к ней AI и собственное пояснение движка:

```
GE-C003  (01)  Check digit validation failed for AI (01) value ''09506000134350''
```

> Удвоенные кавычки в этом сообщении приходят из каталога ошибок движка, а не из этого
> приложения.

### Правка существующего захвата

Щелчок правой кнопкой по захвату → **Сборка** загружает его AI в редактор. Измените значение,
соберите заново — и результат появится как новый захват, а исходный останется нетронутым.

## Режим «Объединение»

Старые этикетки часто распределяют данные по **нескольким штрихкодам GS1-128** — GTIN в одном,
срок годности и партия в другом, — потому что один линейный штрихкод не вмещает всё. Режим
«Объединение» принимает до **трёх** таких штрихкодов, объединяет их в одну строку
элементов, которую нёс бы **GS1 DataMatrix**, и проверяет результат целиком. Когда он
корректен, приложение рисует символ DataMatrix.

Ни один из этих штрихкодов не обязан быть полным сам по себе. Номер партии без своего GTIN
по отдельности не проходит проверку с ошибкой `GE-S005`, но для одного штрихкода из набора это
нормально, поэтому режим «Объединение» проверяет его по объединению.

### Полоса объединения

Переход в режим **Объединение** заменяет строку ввода полосой вдоль нижнего края окна.
История захватов уходит в сторону, потому что сканы режима «Объединение» не являются
захватами и никогда в неё не попадают. Вместо отчёта о захвате в области отчёта показывается
отчёт объединения:

```
┌────────────────────────────────────────────────────────────────────┐
│ [Parse|Build|Combine]   (scanner controls, on Windows)   Options   │
├────────────────────────────────────────────────────────────────────┤
│ Combine report                                   │ Options panel   │
├────────────────────────────────────────────────────────────────────┤
│ [Reset] [Remove Last] │ Barcode: [ …………………………………………… ] [Add]       │
├────────────────────────────────────────────────────────────────────┤
│ 2 of 3 GS1-128 barcodes                                   [About]  │
└────────────────────────────────────────────────────────────────────┘
```

Штрихкод можно ввести двумя способами:

- **Отсканировать.** В Windows элементы управления сканером в режиме «Объединение»
  остаются на панели инструментов, и каждый скан идёт прямо в объединение, а не в историю.
- **Ввести или вставить** в поле *Штрихкод* и нажать <kbd>Enter</kbd> или
  **Добавить**. FNC1 записывается как **`{GS}`**, как и в строке ввода. Штрихкод,
  введённый без AIM Code ID, считается GS1-128.

| Кнопка | Действие |
|---|---|
| **Добавить** | Добавляет штрихкод из поля |
| **Удалить последний** | Убирает последний штрихкод (недоступна, когда их нет) |
| **Сбросить** | Убирает все штрихкоды, очищает поле и любой отказ и начинает заново |

Строка состояния всегда показывает, сколько штрихкодов набрано (*Штрихкодов GS1-128: 2 из 3*), или
почему был отклонён последний.

### Что отклоняет объединение

Отклонённый штрихкод не добавляется. Причину называют и отчёт, и строка состояния:

| Штрихкод | Отклонён, потому что |
|---|---|
| Пустое поле | Нечего добавлять |
| Четвёртый штрихкод | Этикетка объединяется не более чем из трёх. Уберите последний или сбросьте |
| Другая символика по AIM Code ID | Объединяется только GS1-128, поэтому GS1 DataMatrix (`]d2`) или QR Code отклоняется с указанием названия |
| Нечитаемые AI | Синтаксическая ошибка; показываются код ошибки и сообщение движка |
| Совсем нет AI | Нечего объединять |
| Уже отсканированный | Та же строка элементов дважды, например тот же штрихкод, отсканированный снова; отчёт называет, какой более ранний штрихкод он повторяет |

Режим «Объединение» отклоняет только то, что вообще не может использовать. Всё остальное
(неверная контрольная цифра, некорректная дата, недостающий сопутствующий AI) принимается и
оценивается по объединению.

### Дубликаты и конфликты

AI объединяются в порядке сканирования. Когда два штрихкода несут один и тот же AI:

- **с одинаковым значением** он сохраняется один раз и указывается в разделе
  *Дубликаты — сохранены один раз* вместе со штрихкодами, в которых был прочитан;
- **с разными значениями** это **конфликт**. Вердикт гласит *КОНФЛИКТ*, расходящиеся
  значения перечисляются по штрихкодам, и **ничего не объединяется**, пока конфликт не устранён.
  Уберите ошибочный штрихкод или сбросьте.

### Отчёт объединения

Сверху вниз:

1. **Вердикт**: *нет сканов*, *КОНФЛИКТ*, корректно или некорректно, и
   сколько штрихкодов набрано.
2. **Сканы**: каждый штрихкод в том виде, в каком пришёл, его символика и строка элементов,
   оставшаяся после удаления AIM Code ID. Проблема, которую может решить только объединение,
   показана у штрихкода с пометкой *оценивается по объединению*.
3. **Дубликаты** и **конфликты**, если они есть.
4. **Объединено**: строка элементов, её HRI и длина, затем объединённый ввод в виде
   подписанной ленты и по карточке на каждый AI — всё оформлено как в
   [отчёте анализа](#отчёт). Каждая ошибка и каждое предупреждение по объединению затем
   перечислены в разделе *Проверка*.
5. **Символ GS1 DataMatrix** с HRI под ним. Он рисуется, только если объединение корректно.
   Иначе отчёт объясняет, почему символ не нарисован, чтобы некорректный символ нельзя было
   напечатать по ошибке.

Например, этикетка с двумя штрихкодами:

| Штрихкод | Несёт | Сам по себе |
|---|---|---|
| `]C10109506000134352` | (01) GTIN | корректен |
| `]C11726123110LOT-ABC` | (17) срок годности, (10) партия | `GE-S005` для обоих AI, оценивается по объединению |

Они объединяются в `01095060001343521726123110LOT-ABC`, HRI
`(01)09506000134352 (17)261231 (10)LOT-ABC`, что корректно, поэтому символ рисуется. AI `17`
имеет фиксированную длину, поэтому после него FNC1 не нужен. Режим «Объединение» вставляет
его везде, где этого требует стандарт.

**Сохранить отчёт** экспортирует отчёт объединения в HTML или PDF так же, как отчёт анализа
(см. [Экспорт](#экспорт)), как только набран хотя бы один штрихкод. Имя HTML-файла начинается
с `gaia-combine-`.

Отчёт следует выбранному языку и теме. Изменение параметра анализа или языка заново проверяет
уже набранные штрихкоды. Они переживают и переход в режим «Анализ» или «Сборка»
и обратно, но не перезапуск: штрихкоды режима «Объединение» не сохраняются.

## Отчёт

Выбранный захват отображается как полный отчёт: полоса вердикта, строка элементов, разложенная
в размеченную «ленту», метаданные анализа, по карточке на каждый AI с его интерпретациями, а
также ошибки и предупреждения с подсказками, как их устранить.

Для **Digital Link** каждая карточка AI несёт ещё и свою структурную роль — **первичный ключ**,
**квалификатор ключа** или **атрибут данных** — с цветовой пометкой в том порядке, в каком они
идут в URI. Роли показываются только для Digital Link: в обычной строке элементов у AI нет
позиции в URI, которую можно было бы описать.

Отчёт следует выбранным вами языку и теме.

### Экспорт

| | |
|---|---|
| **Сохранить отчёт → Как HTML…** (<kbd>⌘S</kbd>) | Записывает ровно то, что на экране: один самодостаточный файл, открывающийся в любом браузере |
| **Сохранить отчёт → Как PDF…** (<kbd>⌘P</kbd>) | Печатает отчёт через системное окно печати — выберите там назначение PDF |

PDF проходит через окно печати потому, что именно там выбираются назначение и имя файла:
**PDF ▾ → Сохранить как PDF** в macOS, **Microsoft Print to PDF** в Windows, **Печать в файл**
в Linux. Страницы разбиты как положено, а текст остаётся выделяемым.

Печать и PDF всегда используют светлую палитру, даже когда приложение в тёмной теме, и
сохраняют цветные метки AI и полосу вердикта.

Если на машине не настроены ни принтер, ни назначение PDF, приложение сообщит об этом и укажет
на экспорт в HTML, который печатается из любого браузера.

## Параметры анализа

Панель справа собирает все параметры движка. Изменение любого из них **тут же заново
анализирует выбранный захват**, так что панель служит и способом спросить «а как этот ввод
выглядел бы с такими настройками?», а не только влияет на следующий скан.

| Параметр | Значения |
|---|---|
| Режим анализа | `SYNTAX`, `CONTENT`, `DATA_CARRIER`, `INTERPRETATION` — насколько глубоко вести разбор |
| Язык | 35 каталогов сообщений |
| Порядок | `LITTLE` (дд/мм/гггг), `MIDDLE` (мм/дд/гггг), `BIG` (гггг/мм/дд) |
| Разделитель | `SLASH`, `HYPHEN`, `PERIOD` |
| Месяц | `TWO_DIGIT` (12), `THREE_LETTER` (DEC) |
| Год | `FOUR_DIGIT` (2026), `TWO_DIGIT` (26) |
| Пропустить проверку «requires» | Перестаёт отклонять AI, у которого нет обязательного спутника (`GE-S005`) |
| Пропустить проверку «excludes» | Перестаёт отклонять сочетания AI, которые запрещает стандарт (`GE-S006`) |

*Сбросить к значениям по умолчанию* внизу панели возвращает собственные значения движка.

### Первый запуск

Пока ничего не сохранено, приложение берёт настройки из **региональных параметров вашей
машины**, а не из значений по умолчанию движка:

- **язык** берётся из системной локали, с возвратом к английскому, если каталога для неё нет;
- **параметры даты** считываются из короткого формата даты вашей локали: порядок составных
  частей, разделитель и то, сокращаются ли месяц и год.

> **Примечание.** Локаль, записывающая короткие даты с двузначным годом, и здесь начнёт с двух
> цифр: это совпадает с остальной системой, но отличается от значения по умолчанию в движке,
> где год четырёхзначный. Измените его в панели — и выбор сохранится.

## Языки

Выбор языка меняет **всё приложение** — меню, кнопки, редактор, панель параметров, строку
состояния и отчёт, — а не только сообщения об ошибках. Языки с письмом справа налево
разворачивают окно и отчёт.

Доступны все 35 языков, с двумя уровнями охвата:

| | Охват |
|---|---|
| Отчёты анализа и все сообщения об ошибках движка | **все 35 языков** |
| Меню, кнопки и подписи самого приложения | **все 35 языков** |

Языки с письмом справа налево — арабский, египетский арабский, персидский и урду —
разворачивают окно и отчёт с самого момента открытия приложения.

Язык запоминается между запусками. Чтобы открыть на другом языке лишь один раз, см.
[`--language`](#запуск).

Кое-что намеренно оставлено без перевода на всех языках: короткие имена полей рядом с «сырыми»
значениями (`format`, `position`, `raw`, `len` …) — это идентификаторы, а не слова; названия
примеров и символик — это термины GS1 и отрасли; и один длинный абзац из стандарта, где
половинчатый перевод ввёл бы в заблуждение.

## Что запоминается

Два файла в каталоге `.gaia-desktop` внутри вашего домашнего каталога:

| Файл | Содержит |
|---|---|
| `options.properties` | Все параметры анализа, тему, признак открытой панели параметров, последний использованный сканер, режим, в котором оставили окно, и настройки проверки обновлений — включена ли она, когда запускалась последний раз и какую версию вы решили пропустить |
| `captures.tsv` | Историю захватов, новые сверху, не более 500 записей |

Параметры записываются при каждом изменении; история — при каждом её изменении. Оба файла
перезаписываются при выходе.

Удаление любого из файлов сбрасывает только эту часть и ничего больше: их держат порознь, чтобы
испорченная история не стоила вам настроек. Файл, испорченный правкой вручную, тоже не
катастрофа: каждая настройка возвращается к своему умолчанию по отдельности, поэтому одна
неверная строка стоит только этой строки.

История хранит ввод, а не результат разбора. При загрузке он разбирается заново — значит,
восстановленный захват отражает параметры, действующие **сейчас**, а не те, что действовали в
момент захвата.

Штрихкоды, набранные в режиме «Объединение», не сохраняются: после перезапуска режим
«Объединение» начинается с пустого списка.

## Сочетания клавиш

| | |
|---|---|
| <kbd>Enter</kbd> | Разобрать содержимое строки ввода |
| <kbd>⌘O</kbd> | Открыть текстовый файл |
| <kbd>⌘S</kbd> | Сохранить отчёт как HTML |

| <kbd>⌘Q</kbd> | Выйти |

штрихкод. Там FNC1 вводится как `{GS}`; <kbd>⌘G</kbd> относится к строке ввода режима
«Анализ».

## Устранение неполадок

| Признак | Причина и решение |
|---|---|
| Приложение не запускается или сообщает `NoClassDefFoundError` | Каталог `lib/` должен лежать рядом с JAR-файлом. Держите их вместе или используйте самодостаточную сборку |
| *«Unsupported JavaFX configuration…»* в консоли при запуске | Ожидаемо и безвредно — библиотека лишь отмечает, как она была загружена. Приложение работает нормально |
| Вставленный разделитель как будто исчезает | Так и задумано: он переписывается в видимый токен `{GS}`, а анализатор всё равно получает настоящий символ. См. [токен {GS}](#строка-ввода-и-токен-gs) |
| Нет кнопки *Подключить сканер* | Вы работаете в macOS или Linux, где драйверов сканера не существует. См. [Сканирование](#сканирование) |
| Сканер не подключается | Проверьте, что логическое имя в списке соответствует вашей модели, что сканер подключён и что его не удерживает другое приложение. [Руководство по настройке сканера Zebra](GaiaDesktop-Zebra-Scanner-Windows-Russian.md#11-устранение-неполадок) перечисляет все коды ошибок. |
| Экспорт в PDF сообщает об отсутствии назначения | На машине не настроены ни принтер, ни назначение PDF. Добавьте его либо экспортируйте в HTML и печатайте из браузера |
| Пункт меню показывает что-то вроде `act.hri` | Пропущена подпись — пожалуйста, сообщите об этом; это дефект сборки, а не настройка |

## Ограничения

- **Сканирование работает только в Windows**, потому что только там есть драйверы.
- **PDF проходит через окно печати**, а не через окно сохранения.
- **Цели Digital Link принимают домен и префикс пути**, но не дополнительные параметры запроса
  и не фрагмент.
- **AI может встречаться лишь однажды** в строке элементов — это правило GS1, а не ограничение
  приложения.
- **Режим «Объединение» принимает только штрихкоды GS1-128, не более трёх**, и не хранит
  их между запусками.
