## மாட்யூல் ஒரு பார்வையில்

```
tools.pantheum:gaia-desktop:1.0.0   Java 21 · JavaFX 21
        └── depends on tools.pantheum:gaia:1.1.0
```

இது மைய நூலகத்தின் ஒரு கிளையன்ட், அதற்கு மேல் எதுவுமில்லை. இதில் **எந்த GS1 அறிவும் பதிக்கப்படவில்லை**: ஒவ்வொரு AI
வரையறையும், சரிபார்ப்பு விதியும், பிழைச் செய்தியும், உள்ளூர்மயமாக்கப்பட்ட விளக்கமும்
[`GaiaParser`](../../../../gaia/docs/GaiaParser.md) மற்றும் [`GaiaBuilder`](../../../../gaia/docs/GaiaBuilder.md)
ஆகியவற்றிலிருந்தே வருகின்றன. குறிப்பாக, AI பட்டியல் இந்த மாட்யூலுக்குள் ஒருபோதும் நகலெடுக்கப்படுவதில்லை — பில்டரின்
தேர்வி மையத்தின் சொந்தப் பதிவேட்டைப் படிக்கிறது, எனவே பில்டர் நிராகரிக்கும் AI ஒன்றை அது வழங்க முடியாது.

**நுழைவுப் புள்ளிகள்:** `tools.pantheum.gaia.desktop.GaiaDesktopApp` (JavaFX `Application`) மற்றும்
`tools.pantheum.gaia.desktop.Launcher` (பொதியாக்கப்பட்ட jar இன் `Main-Class`).

இந்த மாட்யூல் ஒரு இலை (leaf): எதுவும் இதைச் சார்ந்திருக்கவில்லை, இதுவும் வேறு எந்தக் கீழ்நிலை மாட்யூலையும் சார்ந்திருக்கவில்லை.

## கட்டமைத்தல் மற்றும் இயக்குதல்

- இயக்க **Java 21**, கட்டமைக்க JDK 21 அல்லது புதியது — மாட்யூல் `release=21` உடன் தொகுக்கப்படுகிறது. JavaFX 21 அதற்குப்
  பொருந்தும் LTS வரிசை. மைய jar இன்னும் Java 11 பைட்கோடு, 21 இல் மாற்றமின்றி இயங்குகிறது.
- `PATH` இல் **Maven**. இந்தக் களஞ்சியத்தில் wrapper இல்லை.
- **முதலில் மையத்தை நிறுவுங்கள்.** இந்த மாட்யூல் `gaia:1.1.0` ஐ `~/.m2` இலிருந்து பெறுகிறது; பழைய அல்லது இல்லாத மைய jar
  தான் வழக்கமாக `package tools.pantheum.gaia does not exist` க்குக் காரணம்.

```bash
(cd gaia && mvn -q install -DskipTests)      # publish the core
(cd gaia-desktop && mvn javafx:run)          # run from source
(cd gaia-desktop && mvn clean package)       # target/dist/gaia-desktop-<version>-<platform>/ — jar (~290 KB), lib/, run.sh (run.bat on win)
(cd gaia-desktop && mvn clean -Pfat package) # one self-contained jar, ~50 MB
(cd gaia-desktop && mvn package -Dfx.platform=win)   # another platform; see Packaging
java -jar gaia-desktop/target/dist/gaia-desktop-1.0.0-mac-aarch64/gaia-desktop.jar
java -jar gaia-desktop/target/dist/gaia-desktop-1.0.0-mac-aarch64/gaia-desktop.jar --language=FR
```

`--language` ஒன்றே கட்டளை-வரி அளவுரு, மேலும் முழு சுயவிவரத்தையும் வேறிடத்துக்குத் திருப்பும் `-Dgaia.desktop.home=…`
தவிர, தொடக்கத்தைப் பாதிக்கும் ஒரே வழி.

`mvn javafx:run` என்பது மேம்பாட்டு வழி: செருகுநிரல் JavaFX ஐ **மாட்யூல் பாதையில்** வைக்கிறது, எனவே கருவித்தொகுப்பு பெயருள்ள
மாட்யூலாகத் தொடங்குகிறது, `GaiaDesktopApp` ஐ நேரடியாகத் தொடங்கலாம். பொதியாக்கப்பட்ட jar அதைச் செய்ய முடியாது — அதில்
எல்லாம் கிளாஸ் பாதையில் இருக்கும் — அதனால்தான் அதன் `Main-Class` என்பது `Launcher` இடைமுகம். அந்த அமைப்பில் `Main-Class`
ஆக `Application` துணைக்கிளாஸ் இருந்தால் *"JavaFX runtime components are missing"* உடன் தோல்வியடைகிறது.

எப்போதும் `clean` ஐப் பயன்படுத்துங்கள் — தளங்களின் தொகுப்பைக் கட்டமைப்பதற்கு முன் ஒருமுறை, ஏனெனில் அது `target/dist/`
இலிருந்து அனைத்தையும் காலியாக்குகிறது. காரணத்துக்கு [கட்டமைப்புச் சிக்கல்களைத் தீர்த்தல்](#கட்டமைப்புச்-சிக்கல்களைத்-தீர்த்தல்)
பார்க்கவும்.

### பொதியாக்கம்

அனுப்பக்கூடிய அனைத்தும் `target/dist/gaia-desktop-<version>-<platform>/` கீழ் சேகரிக்கப்படுகின்றன, வேறு எதுவும் இல்லை,
எனவே `target/` இல் `classes/`, `maven-status/` மற்றும் கட்டமைப்பின் மீதமுள்ள தற்காலிகக் கோப்புகளின் அருகிலிருந்து
கலைப்பொருட்களைப் பொறுக்காமலேயே அந்தக் கோப்பகத்தை ஒரு தொகுப்பாக zip செய்யலாம் அல்லது நகலெடுக்கலாம். `${dist.dir}` அதற்கு
ஒரே இடத்தில் பெயரிடுகிறது; கலைப்பொருள் எழுதும் ஒவ்வொரு செருகுநிரலும் அதையே சுட்டுகிறது.

#### ஒவ்வொரு தளத்திற்கும் ஒரு கட்டமைப்பு

JavaFX jar கள் நேட்டிவ் குறியீட்டைக் கொண்டுள்ளன, எனவே ஒவ்வொரு விநியோகமும் ஒரே தளத்துக்கானது, அதன் பெயரை `fx.platform`
பண்பு OpenJFX வகைப்படுத்தியாகத் தருகிறது: `mac-aarch64`, `mac`, `win`, `linux` அல்லது `linux-aarch64`. OS ஐப் பொறுத்துச்
செயல்படும் ஐந்து `fx-*` சுயவிவரங்கள் அதைக் கட்டமைக்கும் இயந்திரத்தின் சொந்தத் தளத்துக்கு அமைக்கின்றன, சாதாரண
`mvn package` அல்லது `mvn javafx:run` க்குத் தேவையானது அவ்வளவே; `-Dfx.platform=…` அவற்றை மீறி எந்த இயந்திரத்திலிருந்தும்
வேறு எந்தத் தளத்தையும் கட்டமைக்கிறது — JavaFX jar கள் வெறும் பதிவிறக்கங்கள். `${dist.dir}` என்பது
`target/dist/${fx.platform}`, எனவே ஒரு தளத்தின் கட்டமைப்பு மற்றொன்றின் கட்டமைப்பை ஒருபோதும் மேலெழுதுவதில்லை.

```bash
(cd gaia-desktop && mvn -q clean package)    # this machine's platform, with the tests
for p in win linux mac mac-aarch64; do (cd gaia-desktop && mvn -q package -DskipTests -Dfx.platform=$p); done
```

இரண்டு pom விவரங்கள் இதைச் செயல்பட வைக்கின்றன, இரண்டுமே நீக்கக்கூடியவை போலத் தோன்றும்:

- **ஒவ்வொரு JavaFX மாட்யூலும் நேரடிச் சார்பு** — base, graphics, controls, media மற்றும் web — ஒவ்வொன்றும்
  `<classifier>${fx.platform}</classifier>` மற்றும் ஒரு `org.openjfx:*` விலக்குடன். OpenJFX இன் pom கள் தங்கள் மறைமுக
  (transitive) jar களை *கட்டமைக்கும் இயந்திரத்தின்* OS ஐப் பொறுத்துத் தேர்ந்தெடுக்கின்றன, எனவே graphics அல்லது base ஐ
  மறைமுகமாக வர விட்டால் Windows கட்டமைப்பில் Windows நேட்டிவ்களுக்கு அருகில் Mac நேட்டிவ்களும் சேர்ந்துவிடும்.
- **பண்பு `fx.platform`, `javafx.platform` அல்ல.** வெளியிலிருந்து அமைக்கப்பட்டால், OpenJFX இன் சொந்தப் பண்பை அதன் பெற்றோர்
  pom தன்னைக் கொண்டே மறுவரையறை செய்கிறது; Maven அந்த pom ஐச் செல்லாதது என நிராகரித்து, தள jar களை அமைதியாகக் கைவிடுகிறது,
  JavaFX இல்லாத கட்டமைப்பு மிஞ்சுகிறது.

இரண்டு அமைப்புகளும் ஒரே பாதையை எழுதுகின்றன, `target/dist/gaia-desktop-<version>-<platform>/gaia-desktop.jar`, ஒவ்வொரு
கட்டமைப்பிலும் அவற்றில் சரியாக ஒன்று மட்டுமே இயங்குகிறது. `${jar.phase}`, `assembly.skipAssembly` மற்றும் `mdep.skip`
தான் இரண்டும் அதை உரிமைகோருவதைத் தடுக்கின்றன.

| | இயல்புநிலை | `-Pfat` |
|---|---|---|
| `gaia-desktop.jar` | ~290 KB — இந்த மாட்யூலின் கிளாஸ்களும் வளங்களும் மட்டும் | ~50 MB — சார்புகள் அதற்குள் பிரிக்கப்பட்டுள்ளன |
| `dist/gaia-desktop-<version>-<platform>/lib/` | 17 jar கள், மேனிஃபெஸ்ட் `Class-Path` இல் ஒவ்வொன்றாகப் பெயரிடப்பட்டவை | — |
| அனுப்புவது | jar **மற்றும்** அதன் அருகில் `lib/` | ஒரே கோப்பு |
| `dist/gaia-desktop-<version>-<platform>/` இல் மேலும் | `run.bat` (win) அல்லது `run.sh` (மற்றவை) | அதுவே |
| மேலும் | `readme.html` மற்றும் `docs/` (ஒவ்வொரு தளமும்) | அதுவே |

ஒவ்வொரு விநியோகமும் வழிகாட்டிகளையும் கொண்டுள்ளது: `docs/` அதன் அமைப்புடன் நகலெடுக்கப்படுகிறது, எனவே வழிகாட்டிகளுக்கும்
மொழிபெயர்ப்புகளுக்கும் இடையிலான இணைப்புகள் தொடர்ந்து செயல்படுகின்றன, மொழிபெயர்ப்புக் கருவிகள் (`check-i18n.py`,
`i18n-manifest.json`, `i18n-plan.md`) நீங்கலாக; மேலும் மூலத்தில் `readme.html`, ஒவ்வொன்றுக்கும் இணைக்கும் அட்டவணை,
`src/main/dist/readme.html` இலிருந்து, அதில் `@VERSION@` pom பதிப்பாக மாற்றப்படுகிறது. இரண்டையும் `pick-launch-script`
antrun படி எழுதுகிறது, நீக்கப்பட்ட வழிகாட்டி தங்கிவிடாமல் இருக்க அது முதலில் `docs/` ஐ நீக்குகிறது. readme இணைப்புகள் கையால்
எழுதப்பட்டவை — `docs/` கீழ் ஒரு வழிகாட்டியின் பெயரை மாற்றினாலோ மொழிபெயர்ப்பைச் சேர்த்தாலோ அங்கும் அதன் வரிசை தேவை.

மேனிஃபெஸ்ட் `Class-Path` உம் `lib/` உம் ஒரே விஷயத்தின் இரண்டு பாதிகள்: jar ஒவ்வொரு இயக்க நேரச் சார்புக்கும்
`lib/<artifact>-<version>.jar` எனப் பெயரிடுகிறது, `copy-dependencies` சரியாக அந்தப் பெயர்களைக் கொண்டு `lib/` ஐ
நிரப்புகிறது. அதுவே `java -jar` செயல்படக் காரணம்.

#### macOS செயலி மற்றும் விநியோக zip

ஒரு antrun செயலாக்கம், `mac-app-and-zip`, `package` கட்டத்தை முடிக்கிறது. அந்தக் காரணத்தால்தான் antrun செருகுநிரல் jar
மற்றும் assembly செருகுநிரல்களுக்கு **பின்னர்** அறிவிக்கப்பட்டுள்ளது — Maven ஒரு கட்டத்தின் செயலாக்கங்களைச் செருகுநிரல்
அறிவிப்பு வரிசையில் இயக்குகிறது — எனவே அது இயங்கும்போது jar, எந்தப் பொதியாக்கத்திலும், ஏற்கனவே இருக்கும். (அதன் மற்றொரு
செயலாக்கமான `pick-launch-script`, `prepare-package` இல் உள்ளது, பாதிக்கப்படுவதில்லை.)

`mac` மற்றும் `mac-aarch64` க்கு அது முதலில் விநியோகக் கோப்பகத்தில் `GAIA Desktop.app` ஐக் கட்டமைக்கிறது: `Info.plist`
(`@VERSION@` pom பதிப்பாக மாற்றப்பட்டு), தொடக்கி `Contents/MacOS/gaia-desktop` (இயக்கக்கூடியதாக்கப்பட்டு) மற்றும்
`gaia-desktop.icns`, அனைத்தும் `src/main/macos/` இலிருந்து, பின்னர் `gaia-desktop.jar` மற்றும் `lib/` ஐ `Contents/Java`
க்குள் **நகர்த்துகிறது**, எனவே தொகுப்பு தனித்து நிற்கிறது. அருகில் jar இல்லாதபோது `run.sh` அங்கே பார்க்கிறது. தொடக்கி
பதிப்பின்படி Java ஐத் தேடுகிறது (`java_home -v 21+`, பின்னர் Homebrew openjdk — Finder இலிருந்து தொடங்கினால் `JAVA_HOME`
அல்லது `PATH` தெரியாது), எதுவும் இல்லையெனில் `osascript` மூலம் உரையாடலைக் காட்டுகிறது, logback இன் சார்புப் பாதை `logs/`
எழுதக்கூடியதாக இருக்க `~/.gaia-desktop` க்கு `cd` செய்கிறது, மேலும் `-Xdock:name`/`-Xdock:icon` ஐ அனுப்புகிறது. macOS
இயங்கும் `java` ஐத் தொகுப்புடன் இணைக்கிறது (அதன் bundle id உம் Dock சின்னமும் செயலியினுடையவை); மெனு பட்டியில் GAIA
Desktop தெரிகிறது.

பின்னர், ஒவ்வொரு தளத்துக்கும், அது Ant இன் `<zip>` கொண்டு கோப்பகத்தை அதே பெயருள்ள கோப்புறையின் கீழ்
`target/dist/gaia-desktop-<version>-<platform>.zip` ஆக zip செய்கிறது: `run.sh` மற்றும் `Contents/MacOS/**` ஐ
`filemode="755"` உடன் தனிக் கோப்புத் தொகுப்பாக, இல்லையெனில் unzip செய்த பிறகு அவை இயங்காது. zip **இணைக்கப்படுவதில்லை**:
அது GitHub வெளியீடுகளுக்கானது, நான்கு தளங்களும் நான்கு கட்டமைப்புகளிலிருந்து வருகின்றன, அவற்றை Maven Central — ஒவ்வொரு
பதிப்புக்கும் மாற்ற முடியாத ஒரே பதிவேற்றம் — ஒருபோதும் ஒரே வெளியீடாக ஏற்க முடியாது.

`project.build.outputTimestamp` கட்டமைப்பு நேரத்துக்கு அமைக்கப்படுகிறது. இல்லையெனில் maven-jar-plugin 3.5 மற்றும்
maven-assembly-plugin 3.8 இல் உள்ள காப்பகக் கருவிகள் ஒவ்வொரு உள்ளீட்டுக்கும் 1 பிப்ரவரி 1980 எனத் தேதியிடுகின்றன.

செயலிச் சின்னத்தை `tools/icon/GaiaIcon.java` வரைகிறது (அது கட்டமைப்பின் பகுதி அல்ல; அதன் தலைப்பில் `sips`/`iconutil`
படிகள் உள்ளன). அதன் வெளியீடுகள் களஞ்சியத்தில் சேர்க்கப்பட்டுள்ளன: தொகுப்புக்கு `src/main/macos/gaia-desktop.icns`, மேலும்
`src/main/resources/icons/gaia-desktop-{16..256}.png`, இவற்றை `GaiaDesktopApp` சாளரச் சின்னமாக அமைக்கிறது (Windows
மற்றும் Linux; macOS சாளரச் சின்னங்களைப் புறக்கணிக்கிறது).

#### தொடக்க ஸ்கிரிப்டுகள்

`run.sh` மற்றும் `run.bat` `src/main/scripts/` இலிருந்து வருகின்றன, வடிகட்டாமல் `dist/gaia-desktop-<version>-<platform>/`
க்குள் நகலெடுக்கப்படுகின்றன — `run.sh` இல் `${...}` ஷெல் விரிவாக்கங்கள் நிறைந்துள்ளன, அவற்றை Maven வடிகட்டல் விருப்பப்படி
மாற்றி எழுதக்கூடும். பின்னர் ஒரு antrun படி தளம் இயக்குவதை மட்டுமே வைத்துக்கொள்கிறது — `win` க்கு `run.bat`, மற்ற
அனைத்துக்கும் `run.sh` — மேலும் `run.sh` இல் இயக்கப் பிட்டை அமைக்கிறது, ஏனெனில் `copy-resources` அதைக் கொண்டுசெல்வதில்லை.
அது சுயவிவரங்கள் மூலம் அல்லாமல் தீர்மானிக்கப்பட்ட `${fx.platform}` இலிருந்து முடிவு செய்கிறது, ஏனெனில் சுயவிவரச் செயல்படுத்தல்
மற்றொரு சுயவிவரம் அமைத்த மதிப்பைக் காண முடியாது: இல்லையெனில் Windows இல் செய்த Linux கட்டமைப்புக்கு ஹோஸ்டின் ஸ்கிரிப்ட்
கிடைத்திருக்கும்.

அவை **மேனிஃபெஸ்டைச் சார்ந்திருப்பதில்லை**. ஒவ்வொன்றும் கிளாஸ் பாதையைத் தானே உருவாக்குகிறது, `gaia-desktop.jar` அதைத்
தொடர்ந்து `lib/` இல் உள்ள ஒவ்வொரு `.jar` உம், `lib/*` வைல்டுகார்டிடம் விடாமல் ஒவ்வொன்றாகப் பெயரிட்டு, எனவே இடைவெளியுள்ள
பாதை ஒரே உள்ளீடாகவே இருக்கும், சேர்க்கப்பட்டவற்றின் எண்ணிக்கை உண்மையானது. `-cp` உடன் தொடங்குவதே அவை
`tools.pantheum.gaia.desktop.Launcher` ஐ வெளிப்படையாகக் குறிப்பிடக் காரணம்: `-cp` மேனிஃபெஸ்டின் `Main-Class` ஐப்
படிப்பதில்லை. ஆனாலும் அது அதன் `Class-Path` ஐ **இன்னும்** பின்பற்றுகிறது — `-cp` இல் உள்ள jar அதன் மேனிஃபெஸ்ட் பெயரிடும்
jar களைக் கொண்டுவருகிறது, அவை அதற்கு உடனே பின்னால் தேடப்படுகின்றன — எனவே ஸ்கிரிப்ட் பட்டியலிட்டாலும் இல்லாவிட்டாலும்
ஒவ்வொரு `lib/` jar உம் ஏற்றப்படுகிறது, ஸ்கிரிப்டின் கிளாஸ் பாதையிலிருந்து ஒன்றை விட்டுவிட்டாலும் அது JVM க்கு வெளியே
இருப்பதில்லை. ஆனாலும் ஸ்கிரிப்டுகள் அனைத்தையும் பட்டியலிடுகின்றன, எனவே மேனிஃபெஸ்ட் பழையதான, கையால் திருத்தப்பட்ட அல்லது ஒரு
உள்ளீடு குறைவான jar உம் தொடங்கும். ஒரே ஸ்கிரிப்ட் இரண்டு பொதியாக்கங்களுக்கும் பயன்படுகிறது: `-Pfat` jar க்குச் சேர்க்க
`lib/` இல்லை, தேவையும் இல்லை, அதனால்தான் காலியான `lib/` ஒரு குறிப்பு மட்டுமே, பிழை அல்ல.

#### Zebra நேட்டிவ் நூலகங்கள்

கட்டமைப்பு Zebra வுடையது எதையும் அனுப்புவதில்லை — DLL களும் இல்லை, சேவை jar களும் இல்லை. Windows இல் அவை இயந்திரத்தில்
நிறுவப்பட்ட Zebra Scanner SDK இலிருந்து வருகின்றன: `run.bat` அதன் `Jpos*.jar` சேவை jar களையும் `bin\` ஐயும் கிளாஸ்
பாதையிலும், `bin\` ஐ `PATH` இலும் சேர்க்கிறது, அங்கே `System.loadLibrary` `CSJPOSScanner.dll` /
`CSJPOSScanner64.dll` ஐக் கண்டுபிடிக்கிறது (`java.library.path` இன் இயல்புநிலை `PATH`). JavaPOS API உம் அதன்
உள்ளமைவு ஏற்றியும் எப்போதும் `lib\javapos-*.jar` இலிருந்தே வருகின்றன, SDK இருந்தாலும் இல்லாவிட்டாலும்.

**`run.bat` SDK இன் சொந்த JavaPOS jar ஐ ஒருபோதும் சேர்ப்பதில்லை**, `External\JavaPOS-1.14.0-Dist\javaPOS114.jar`.
ஒருகாலத்தில் சேர்த்தது, API இன் இரண்டு நகல்களைத் தவிர்க்க `lib\javapos-*.jar` ஐ விட்டுவிட்டு — ஆனால் மேனிஃபெஸ்ட்
`Class-Path` அவற்றை எப்படியும் ஏற்றியது (மேலே பார்க்கவும்), எனவே JVM க்கு இரண்டும் கிடைத்தன: `lib\` இலிருந்து 4.x ஏற்றிக்
கிளாஸ்கள், அவற்றின் அருகில் `javaPOS114.jar` இன் `jpos/res/jpos.properties` உம் `jcl.xsd` உம். அந்தப் பண்புகள் கோப்பு
[`JposConfig`](#ஸ்கேனர்-ஒருங்கிணைப்பு) ஐ ஒதுங்கச் செய்கிறது, அந்த `jcl.xsd` 1.10 வரையிலான JavaPOS பதிப்புகளை மட்டுமே
ஏற்கிறது, எனவே `jpos.xml` இல் உள்ள ஒவ்வொரு உள்ளீடும் (1.12–1.14) சரிபார்ப்பில் தோல்வியடைந்தது, பதிவேடு காலியாகவே இருந்தது,
ஸ்கேனரை அடையும் முன்பே ஒவ்வொரு இணைப்பும் பிழை 109 உடன் தோல்வியடைந்தது. அதற்கு அந்த jar கிளாஸ் பாதையில் இருப்பதே போதும்,
`lib\` இன் jar களுக்குப் பின்னால் இருந்தாலும் கூட. Zebra சேவை jar கள் `lib\` இலிருந்து வரும் 1.14 API இல் மாற்றமின்றி
இயங்குகின்றன — open, claim, ஸ்கேன் ஆகியவை அந்த வழியிலேயே உண்மையான ஸ்கேனருடன் சரிபார்க்கப்பட்டுள்ளன. `run.bat` அருகில்
கையால் வைக்கப்பட்ட DLL கள் இன்னும் மதிக்கப்படுகின்றன: அப்போது ஸ்கிரிப்ட் `-Djava.library.path=<dist>;%PATH%` ஐ
அமைக்கிறது, `PATH` ஐ இறுதியில் சேர்த்து, ஏனெனில் இந்தப் பண்பு இயல்புநிலைத் தேடல் பாதையை முழுமையாக மாற்றுகிறது.

`mvn javafx:run` இவற்றில் எதையும் செய்வதில்லை, எனவே Windows இல் மேம்பாட்டு இயக்கத்திலிருந்து ஸ்கேனரை claim செய்ய SDK jar
களை கிளாஸ் பாதையிலும் அதன் `bin\` ஐ `PATH` இலும் வேறு வழிகளில் வைக்க வேண்டும்; அதற்கு `dist/` இலிருந்து இயக்குங்கள்.

கிளாஸ் பாதைக்கு அப்பால் அவை `java -jar` செய்யாதவற்றையும் கவனிக்கின்றன: எந்தப் பணிக் கோப்பகத்திலிருந்தும் செயல்படத் தங்கள்
சொந்தக் கோப்பகத்தைத் தீர்மானித்தல், `PATH` ஐ விட `JAVA_HOME` க்கு முன்னுரிமை, மேலும் 11 க்கு முந்தைய JVM ஐ
`UnsupportedClassVersionError` க்குப் பதிலாகத் தீர்வைக் கூறும் வாக்கியத்துடன் நிராகரித்தல். `GAIA_DESKTOP_OPTS` JVM
விருப்பங்களைக் கடத்துகிறது. `run.bat` `javaw.exe` அல்ல, `java.exe` ஐப் பயன்படுத்துகிறது, எனவே கன்சோல் திறந்தே இருக்கும் —
ஸ்கேனர் இயங்கும் ஒரே தளம் Windows, அதன் நிலையும் JavaPOS பிழைகளும் அங்கேயே செல்கின்றன.

`run.bat` தான் கண்டுபிடிப்பவற்றிலிருந்து Java, JavaFX மற்றும் Zebra சேவைகளையும் தேர்ந்தெடுக்கிறது — தொகுக்கப்பட்ட `jdk*\`,
மாட்யூல் பாதையில் `javafx-sdk*\lib\`, `ZEBRA_HOME` இல் Zebra Scanner SDK — SDK இன் JavaFX ஐப் பயன்படுத்தும்போது `lib\`
இல் உள்ள JavaFX நகல்களை கிளாஸ் பாதைக்கு வெளியே வைக்கிறது, மேலும் JDK இன் SAX பகுப்பி, Windows பதிலிகள் மற்றும் நம்பிக்கைக்
களஞ்சியம், Java 17+ இல் `--enable-native-access` ஆகியவற்றை அனுப்புகிறது. README இன்
[What `run.bat` adds on Windows](../../../README.md#what-runbat-adds-on-windows) இல் அட்டவணை உள்ளது. கோப்பின் CRLF வரி
முடிவுகளைப் பாதுகாக்கவும்: LF மட்டுமே உள்ள தொகுதிக் கோப்பில் `cmd.exe` ஒரு `call :label` ஐத் தவறவிடக்கூடும். `run.sh` உம்
`--enable-native-access=ALL-UNNAMED` ஐ அனுப்புகிறது — JavaFX தன் சொந்த நேட்டிவ்களை `lib/` இலிருந்து ஏற்றுகிறது, JavaFX
கிளாஸ் பாதையில் இருக்கும்போது அதை உள்ளடக்கும் மாட்யூல் `ALL-UNNAMED` — `run.bat` இல் போலவே, Java பதிப்பைப் படிக்க
முடியாதபோது மட்டுமே தவிர்க்கப்படுகிறது.

இரண்டு அமைப்புகளும் **ஒரே தளத்தின்**, `${fx.platform}` இன், JavaFX நேட்டிவ்களைக் கொண்டுள்ளன, எனவே எதுவும் OS அல்லது
கட்டமைப்பு கடந்து எடுத்துச்செல்லக் கூடியது அல்ல. ஒவ்வொரு இலக்குக்கும் ஒருமுறை கட்டமையுங்கள் — [ஒவ்வொரு தளத்திற்கும் ஒரு
கட்டமைப்பு](#ஒவ்வொரு-தளத்திற்கும்-ஒரு-கட்டமைப்பு) பார்க்கவும்.

> **Eclipse.** `copy-dependencies` செயலாக்கத்தில் ஒரு `<?m2e ignore?>` அறிவுறுத்தல் உள்ளது. m2e திறந்திருக்கும் பணியிடத்
> திட்டத்தை jar க்குப் பதிலாக அதன் `target/classes` கோப்புறைக்குத் தீர்மானிக்கிறது, `copy-dependencies` பொதியாக்கப்படாத
> கலைப்பொருளை நகலெடுக்க மறுக்கிறது (MDEP-187), இதனால் `gaia` திட்டம் இதன் அருகில் திறந்திருக்கும் போதெல்லாம் தானியங்கு
> கட்டமைப்பு தோல்வியடையும். விளைவு: IDE யில் மட்டும் செய்த கட்டமைப்பு `target/dist/gaia-desktop-<version>-<platform>/lib/` ஐ
> நிரப்புவதில்லை; jar ஐயே பயன்படுத்தும் முன் `mvn package` இயக்குங்கள்.

### உள்ளீட்டுப் புனல்

ஒவ்வொரு உள்ளீடும் — தட்டச்சு செய்தது, ஒட்டியது, கோப்பிலிருந்து திறந்தது, ஸ்கேன் செய்தது அல்லது உருவாக்கியது — ஒரே
மெத்தட் மூலம், `MainView.capture(String, ScanSource, String)`, பகுப்பியை அடைகிறது.

செயலி முழுவதும் சுற்றிக் கட்டமைக்கப்பட்ட ஒரே வடிவமைப்பு முடிவு இதுவே. உருவாக்கத்துக்குச் சொந்த அறிக்கை, சொந்த வரலாறு,
சொந்த ஏற்றுமதிப் பாதை தேவையில்லை, ஏனெனில் புனலுக்குப் பிறகு உருவாக்கிய சரத்தை ஸ்கேன் செய்ததிலிருந்து பிரித்தறிய முடியாது.
உள்ளீட்டை உருவாக்கும் புதிய எதுவும் அதன் அருகாக அல்லாமல் அதன் வழியாகவே செல்ல வேண்டும்.

### திரெட்டுகள்

| திரெட் | இயக்குவது |
|---|---|
| JavaFX பயன்பாட்டுத் திரெட் | அனைத்துப் பகுப்பாய்வு, வரைதல் மற்றும் UI. AI அட்டவணைகள் சூடானதும் பகுப்பாய்வு ஒரு மில்லிவினாடிக்கும் குறைவு, எனவே பணியாளர் தேவையில்லை |

| JavaPOS நிகழ்வுத் திரெட் | `ScannerService` மறுஅழைப்புகள். `MainView.FxScannerListener` ஒவ்வொன்றையும் `Platform.runLater` உடன் கடத்துகிறது |

**ஒரு கட்டுப்பாட்டின் தேர்வை அதன் சொந்தத் தேர்வு நிகழ்வுக்குள்ளிருந்து ஒருபோதும் மாற்ற வேண்டாம், கட்டுப்பாட்டை அழிக்கவும்
வேண்டாம்.** இந்தச் செயலியில் மூன்று தனித்தனிச் செயலிழப்புகள் சரியாக இதனால்தான் வந்தன: பாப்அப்பின் சொந்த `clearAndSelect`
க்குள் AI தேர்வியை மீட்டமைத்தல் (`ListViewBehavior` இலிருந்து வந்த `IndexOutOfBoundsException`), மற்றும் மொழிக் காம்போவைக்
கொண்ட பலகத்தை அந்தக் காம்போவின் சொந்தக் கையாளிக்குள்ளிருந்து மறுகட்டமைத்தல். இரண்டும் இப்போது `Platform.runLater` உடன்
ஒத்திவைக்கப்படுகின்றன, காரணங்கள் இரண்டு அழைப்பு இடங்களிலும் பதிவு செய்யப்பட்டுள்ளன.

### மறுகட்டமைப்பும் மறுபெயரிடலும்

மொழி மாற்றம் சட்டகத்தை — மெனுக்கள், கருவிப்பட்டை, விருப்பப் பலகம் — பட்டியலிலிருந்து **மறுகட்டமைக்கிறது**, இது பாதுகாப்பானது
ஏனெனில் அவற்றில் எதுவும் நிலையைக் கொண்டிருப்பதில்லை: `OptionsPane` என்பது `ParseOptions` இன் இருவழிக் காட்சி, எனவே
மதிப்புகள் மாதிரியில் இருக்கின்றன, புதிய பலகம் அவற்றை உடனே மீண்டும் எடுத்துக்கொள்கிறது.

**பயனர் தரவை** வைத்திருக்கும் கட்டுப்பாடுகள் புலங்கள், அவை பதிலாக இருந்த இடத்திலேயே மறுபெயரிடப்படுகின்றன:
`BuilderPane.retext(UiStrings)` AI வரிசைகள், Digital Link புலங்கள், தேர்வு ஆகியவற்றை வைத்திருக்கிறது. அதை மறுகட்டமைத்தால்
நடந்துகொண்டிருக்கும் வேலை வீணாகும் — ஒருமுறை அப்படி நடந்தும் இருக்கிறது.

## {GS} டோக்கன்

JavaFX `TextField` `0x20` க்குக் கீழுள்ள ஒவ்வொரு எழுத்தையும் அமைதியாகக் கைவிடுகிறது (`TextInputControl.filterInput`).
"விசித்திரமாகக் காட்டுகிறது" அல்ல — நீக்குகிறது. தட்டச்சு, ஒட்டுதல், `setText` மற்றும் `insertText` அனைத்தும்
பாதிக்கப்படுகின்றன, எனவே `setText("01…" + GS + "10LOT")` இலிருந்து `"01…10LOT"` கிடைக்கிறது: பொருள் அமைதியாக மாறிய
உறுப்புச் சரம், ஏனெனில் மாறும்-நீள AI இப்போது தனக்குப் பின் வருவதை விழுங்கிவிடுகிறது.

`desktop.parse.GsToken` தான் முழுப் பதில். பிரிப்பான் UI வழியாக நேரடி உரை `{GS}` ஆகப் பயணித்து, பகுப்பிக்குச் செல்லும்
வழியில் மீண்டும் `0x1D` ஆகிறது. இந்த டோக்கன் இங்கே கண்டுபிடிக்கப்பட்டதல்ல — மையத்தின் `ASCIIRevealerUtils.printable`
`0x1D` ஐச் சரியாக இப்படித்தான் காட்டுகிறது, எனவே அறிக்கையிலிருந்து நகலெடுத்த மதிப்பை நேரடியாக உள்ளீட்டுப் பட்டியில் மீண்டும்
ஒட்டலாம்.

உள்ளீட்டுப் புலத்தில் உள்ள `TextFormatter` வடிகட்டி உரை வரக்கூடிய ஒவ்வொரு வழியையும் பிடிக்கிறது — தட்டச்சு, ⌘V, சூழல் மெனு,
இழுத்து விடுதல், `setText` — அதனால்தான் மறுஎழுத்து ஒவ்வொரு கையாளியிலும் அல்லாமல் அங்கேயே உள்ளது.

ஸ்கேனர் பாதை ஒருபோதும் `GsToken` வழியாகச் செல்வதில்லை: ஸ்கேன்கள் பகுப்பியை பைட்டுகளாக அடைகின்றன.

## ஸ்கேனர் ஒருங்கிணைப்பு

`ScannerService` JavaPOS `Scanner` கட்டுப்பாட்டின் உரிமையாளர்: open → claim → enable, ஒவ்வொரு ஸ்கேனுக்குப் பிறகும் தரவு
நிகழ்வை மீண்டும் செயல்படுத்துகிறது. தர்க்கச் சாதனப் பெயர்கள் `src/main/resources/jpos.xml` இலிருந்து வருகின்றன.

**ஒவ்வொரு சாதன அழைப்பும் ஒரே திரெட்டில், `gaia-scanner` இல், இயங்குகிறது, அது சேவை இருக்கும் வரை இருக்கிறது** — ஒருபோதும்
FX திரெட்டில் அல்ல, அழைப்புக்குப் பின் முடியும் திரெட்டில் ஒருபோதும் அல்ல. Zebra சேவை CoreScanner COM API வழியாக JNI மூலம்

### தள வாயில்

`ScannerService.isSupportedPlatform()` ஒரு `os.name` சோதனை, `MainView` எந்த ஸ்கேனர் கட்டுப்பாட்டையும் கட்டமைக்கும் முன் அதைக்
கேட்கிறது: macOS மற்றும் Linux இல் நிலைமாற்றி இல்லை, சாதனத் தேர்வி இல்லை, ஸ்கேனர் மெனு இல்லை (எனவே <kbd>⌘K</kbd> உம்
இல்லை), நிலை லேபிளும் இல்லை. அவை மறைக்கப்படவில்லை — அவை ஒருபோதும் உருவாக்கப்படுவதில்லை.

Zebra தனது JavaPOS சேவைகளை Windows க்கு மட்டுமே அனுப்புகிறது, வேறிடங்களில் எதுவும் முன்கூட்டியே தோல்வியடைவதில்லை: jar கள்
தீர்மானிக்கப்படுகின்றன, கட்டுப்பாடு உருவாகிறது, இறுதியில் நேட்டிவ் அடுக்கு இல்லாததால் தோல்வியடைவது `open()` தான், சில
வினாடிகளும் ஒரு உரையாடலும் கழிந்த பிறகு.

இந்த விதி *சேவைகள்* பற்றியது, JavaPOS பற்றியது அல்ல. பல-தளச் சேவையை அனுப்பும் விற்பனையாளர் இங்கே செயல்படுவார், விதியை
விரிவுபடுத்துவது `supportsJavaPos(String)` இல் மட்டுமான மாற்றம் — அது package-private, `os.name` சரங்களுக்கு எதிராகச்
சோதிக்கப்பட்டது, எனவே கட்டமைப்பை இயக்கும் எந்த இயந்திரத்திலும் இரண்டு பதில்களும் உள்ளடக்கப்படுகின்றன.

start/stop பட்டைகளின் எண்ணிக்கையால் பிரிக்கிறது, அதை JavaPOS அறிவிப்பதில்லை), நான்கு-நிலை அஞ்சல் குறியீடுகள், மற்றும்

## உள்ளூர்மயமாக்கல்

லேபிள்கள் ஒவ்வொரு மொழிக்கும் ஒரு பண்புகள் கோப்பில் `src/main/resources/i18n/ui_<CODE>.properties` கீழ் உள்ளன, மையப்
பிழைப் பட்டியல்களின் அதே குறியீடுகளைப் பயன்படுத்தி (`EN`, `FR`, `PCM`, …). 35 உம் உள்ளன, 35 உம் ஒரே மாதிரியான விசைத்
தொகுப்பைக் கொண்டுள்ளன. கோப்புகள் **UTF-8** ஆகப் படிக்கப்படுகின்றன, `Properties` கருதும் ISO-8859-1 ஆக அல்ல, எனவே
மொழிபெயர்ப்புகள் `\uXXXX` தப்பிப்புகளாக அல்லாமல் படிக்கக்கூடிய வடிவில் சேமிக்கப்படுகின்றன.

**பின்வாங்கல் ஒவ்வொரு விசைக்கும், ஒவ்வொரு கோப்புக்கும் அல்ல** — பகுதியளவு மொழிபெயர்க்கப்பட்ட மொழியை அதன் முதல் விசை வந்த
கணத்திலிருந்தே பயனுள்ளதாக்குவது இதுவே. ஆங்கிலமே ஒப்பந்தம்: ஒவ்வொரு விசையும் அங்கே இருக்க வேண்டும்.

| அடுக்கு | விசைகள் | பரப்பு |
|---|---|---|
| பகிரப்பட்ட அறிக்கைச் சொற்களஞ்சியம் | 31 | அனைத்து 35 மொழிகளும் |
| டெஸ்க்டாப் சட்டகம் — மெனுக்கள், பொத்தான்கள், பில்டர், விருப்பங்கள், நிலை வரி, அறிக்கை அமைப்பு, ஸ்கேனர் நிலை, உரையாடல் உரைகள் | 114 | அனைத்து 35 மொழிகளும் |

பகிரப்பட்ட சொற்களில் ஆறு (`generated`, `status`, `dlRole`, `interpretations`, `message`, `level`) இந்தச் செயலியின்
அறிக்கையில் பயன்படுத்தப்படுவதில்லை.
அவை வேண்டுமென்றே வைக்கப்பட்டுள்ளன; கோப்புத் தலைப்பு அதைக் கூறுகிறது.

### `--language` அளவுரு

`GaiaDesktopApp.languageOverride()` JavaFX இன் சொந்த `getParameters().getNamed()` மூலம் `--language=…` ஐப் படித்து,
`Languages.fromArgument` உடன் தீர்மானிக்கிறது — பட்டியல் குறியீடு, enum பெயர், அல்லது BCP 47 குறிச்சொல், பெரிய-சிறிய
எழுத்து வேறுபாடின்றி — `MainView` இடம் ஒப்படைக்கிறது.

**இந்த மேலெழுதல் இயக்கத்துக்கானது, கோப்புக்கானது அல்ல.** `MainView` தான் ஏற்றிய மொழியை `savedLanguage` இல் வைத்து, *அதையே*
திரும்ப எழுதுகிறது, பயனர் தாமே ஒரு மொழியைத் தேர்ந்தெடுத்தார் என்று `languageChosenInSession` சொல்லும் வரை; அதன் பிறகு
அவர்களின் தேர்வு வழக்கம்போல் நிலைக்கிறது. அந்தப் பிரிவே முழு வடிவமைப்பு: கியோஸ்க் சுயவிவரம் அல்லது டெமோ குறுக்குவழி இயந்திர
உரிமையாளர் நாளை திறக்கும் மொழியை மாற்றி எழுதாமலே ஸ்பானிஷில் திறக்கலாம், அதே நேரம் விருப்பப் பலகத்தில் செய்த உண்மையான தேர்வு
நிலைத்திருக்கும்.

எந்தப் பட்டியலையும் குறிப்பிடாத மதிப்பு ஏற்கப்படும் குறியீடுகளுடன் பதிவு செய்யப்பட்டுப் புறக்கணிக்கப்படுகிறது. குறுக்குவழியில்
உள்ள ஒரு எழுத்துப்பிழைக்காகத் தொடங்க மறுப்பது மோசமான தோல்வியாக இருக்கும், அதே காரணத்துக்காக `Languages.fromArgument`
விதிவிலக்கை வீசாமல் `null` ஐத் திருப்புகிறது.

### மொழியைச் சேர்த்தல்

குறியீட்டு மாற்றம் தேவையில்லை.

1. `ui_<CODE>.properties` ஐத் திருத்துங்கள் — ஒவ்வொரு மொழிக்கும் ஏற்கனவே கோப்பு உள்ளது.
2. மதிப்புகளை மொழிபெயருங்கள். `{0}` / `{1}` ஒதுக்கிடங்களை அப்படியே விடுங்கள்.
3. கட்டமையுங்கள். இரண்டு சோதனைகள் ஒப்பந்தத்தைச் செயல்படுத்துகின்றன: ஆங்கிலம் வரையறுக்காத விசையைக் குறியீடு கேட்டால் ஒன்று
   தோல்வியடைகிறது, எந்தப் பட்டியலின் விசைத் தொகுப்பும் ஆங்கிலத்திலிருந்து விலகினால் மற்றொன்று தோல்வியடைகிறது.

முதல் சோதனை கிளாஸ்கள் மீது பிரதிபலிப்பு செய்யாமல் **மூலக் குறியீட்டில்** விசை நேரடிகளைத் தேடுகிறது, ஏனெனில் விசைகள் அழைப்பு
இடங்களில் சர நேரடிகளாக மட்டுமே உள்ளன. அதனால்தான் புதிய செய்தியை மாறி மூலம் தேடாமல் விசையை நேரடியாக எழுதிக்
கட்டமைக்க வேண்டும் — `strings.format("st.scannerError", …)` — இல்லையெனில் சோதனையால் அதைக் காண முடியாது.

### வேண்டுமென்றே மொழிபெயர்க்கப்படாதவை

- மூல மதிப்புகளின் அருகே மோனோஸ்பேஸில் காட்டப்படும் சுருக்கமான புலப் பெயர்கள் — உறுப்பு அட்டையின் `format`, `position`,
  `length`, `raw` மற்றும் `part`, நாடாவின் `AI`, `sep`, `pos` மற்றும் `len`, பிழையின் இடத்தைக் காட்டும் நான்கு கலங்கள்
  (`AI`, `position`, `level`, `stage`), இவற்றின் மதிப்புகள் எப்படியும் மொழிபெயர்க்கப்படாத enum பெயர்களே;
- GS1 கட்டமைப்புகளைப் பெயரிடும் மாதிரி-உள்ளீட்டுப் பெயர்கள், மற்றும் தனிப்பெயர்களான சிம்பாலஜிப் பெயர்கள்;
- `GE-C084` தீர்வுப் பத்தி — அரைகுறை மொழிபெயர்ப்பு ஆங்கிலத்தை விட மோசமான தர உரைநடை;
- `ElementBuilder` இன் தெரியாத-AI கடைசித் தடுப்பு, இதை UI யிலிருந்து அடைய முடியாது: திருத்தி தெரியாத AI களைத் தானே
  சரிபார்த்துப் பட்டியலிலிருந்து அவற்றை அறிவிக்கிறது;
- பதிவு வரிகள்.

ஒரு இடைவெளி மீதமுள்ளது: `ScanSource.label()` வரலாற்று வரிசைக்கும் அறிக்கைத் தலைப்புக்கும் `manual` / `scanner` / `file` /
`built` ஐ ஆங்கிலத்தில் வழங்குகிறது. அதை மூட ஒரு விசைக்கு மேல் தேவை — `HistoryCell` க்கு `UiStrings` இல்லை, பட்டியலின்
கலத் தொழிற்சாலை ஒருமுறை மட்டுமே நிறுவப்படுகிறது, எனவே மொழி மாறும்போது கலங்களையும் புதுப்பிக்க வேண்டியிருக்கும்.

## சேமித்த நிலையின் வடிவங்கள்

`~/.gaia-desktop/` கீழ் இரண்டு கோப்புகள், அவை வெவ்வேறு வேகங்களில் மாறுவதால் தனியாக வைக்கப்பட்டுள்ளன — சிதைந்த அல்லது கையால்
திருத்தப்பட்ட பிடிப்புப் பதிவு பயனரின் அமைப்புகளை இழக்கச் செய்யக்கூடாது. கோப்பகத்தை `-Dgaia.desktop.home=…` உடன்
மேலெழுதுங்கள், இதனால்தான் சோதனைகள் உண்மையான வீட்டுக் கோப்பகத்திலிருந்து விலகி இருக்கின்றன.

**`options.properties`** — ஒரு விருப்பம் மாறும்போதும், வெளியேறும்போதும் எழுதப்படுகிறது.

| விசை | பொருள் |
|---|---|
| `parse.mode`, `parse.language` | குழாய்வழி ஆழமும் செய்தி மொழியும் |
| `date.endian`, `date.separator`, `date.month`, `date.year` | தேதிக் காட்சி |
| `check.skipRequires`, `check.skipExcludes` | கட்டமைப்புச் சோதனைத் தவிர்ப்புகள் |
| `ui.theme` | `LIGHT` அல்லது `DARK` |
| `ui.optionsPane` | விருப்பப் பலகம் திறந்துள்ளதா? |
| `ui.scannerDevice` | கடைசி JavaPOS தர்க்கப் பெயர் |
| `ui.mode` | `PARSE`, `BUILD` அல்லது `COMBINE` |
| `update.check` | தினசரி புதுப்பிப்புச் சரிபார்ப்பு இயங்குகிறதா (இயல்புநிலை `true`) |
| `update.lastCheck` | அது கடைசியாக எப்போது இயங்கியது, ISO-8601; இல்லையெனில் அல்லது படிக்க முடியாவிட்டால் சரிபார்ப்பு நிலுவையில் உள்ளது |
| `update.skipVersion` | பயனர் *இந்தப் பதிப்பைத் தவிர்* தேர்ந்தெடுத்த வெளியீடு; தானாக மீண்டும் வழங்கப்படுவதில்லை |

இல்லாத அல்லது சேதமடைந்த கோப்பு ஒருபோதும் உயிர்க்கொல்லியல்ல: ஒவ்வொரு மதிப்பும் தனித்தனியாகப் பின்வாங்குகிறது, எனவே ஒரு
மோசமான வரி அந்த வரியை மட்டுமே இழக்கச் செய்கிறது, வேறு எதையும் அல்ல. முதல் தொடக்கத்தில், கோப்பே இல்லாதபோது, விருப்பங்கள்
GAIA வின் உள்ளமைந்த இயல்புநிலைகளிலிருந்து அல்லாமல் `SystemDefaults` மூலம் இயந்திரத்தின் பிராந்திய அமைப்புகளிலிருந்து
நிரப்பப்படுகின்றன — இடத்தின் சுருக்கத் தேதி முறை கூறுகளின் வரிசை, பிரிப்பான், மாதமும் ஆண்டும் சுருக்கப்பட்டுள்ளனவா என்பதைத்
தருகிறது.

`Properties.setProperty` க்கு ஒருபோதும் null கொடுக்காதீர்கள்: அது விதிவிலக்கை வீசுகிறது, `persistOptions()` UI நிகழ்வுக்
கையாளிகளிலிருந்து இயங்குகிறது, அங்கே விதிவிலக்கு FX திரெட்டுக்குத் தப்பிவிடுகிறது. இது இந்தச் செயலிக்கு ஏற்கனவே நடந்த
உண்மையான செயலிழப்பு.

**`captures.tsv`** — வரலாறு மாறும்போதும், வெளியேறும்போதும் எழுதப்படுகிறது. புதியது முதலில், அதிகபட்சம் **500** உள்ளீடுகள்.

```
captured(ISO)              <TAB> source  <TAB> symbology   <TAB> input
2026-08-09T14:22:05.123    SCANNER       Data Matrix       0109506000134352\x1D10LOT-001
```

மீண்டும் கணக்கிட முடியாதவை மட்டுமே சேமிக்கப்படுகின்றன. `ParseResult` வரிசைப்படுத்தப்படுவது **இல்லை** — ஏற்றும்போது
உள்ளீட்டை மீண்டும் பகுப்பாய்வு செய்து அது மீண்டும் பெறப்படுகிறது, எனவே மீட்டமைக்கப்பட்ட வரலாறு *இப்போது* நடைமுறையில் உள்ள
விருப்பங்களைப் பிரதிபலிக்கிறது. உள்ளீடுகளில் வழக்கமாக FNC1 உம் ஸ்கேனர் வெளியிடும் வேறு எதுவும் இருக்கும், எனவே உள்ளீட்டுப்
புலம் தப்பிக்கப்படுகிறது (`\\`, `\t`, `\n`, `\r`, மேலும் `0x20` க்குக் கீழுள்ள மற்ற அனைத்துக்கும் `\xNN`), கோப்பு
ISO-8859-1 ஆக, பைட் பைட்டாக, படிக்கப்பட்டு எழுதப்படுகிறது.

தேதி பதிவு செய்யத் தொடங்கும் முன் எழுதப்பட்ட கோப்புகளில் கடிகார நேரம் மட்டுமே உள்ளது; அவை இன்னும் ஏற்றப்படுகின்றன, இன்றைய
தேதியுடன், ஏனெனில் உண்மையான தேதி ஒருபோதும் எழுதப்படவில்லை.

## சோதனை

```bash
(cd gaia-desktop && mvn test)
```

96 சோதனைகள், வேண்டுமென்றே **JavaFX கருவித்தொகுப்பு இல்லாமல்**, இது அவற்றை வேகமாகவும் தலையில்லாமலும் வைக்கிறது. அவை
அறிக்கை வரைவி, உருவாக்கத் தர்க்கம் மற்றும் AI தேடல்கள், `{GS}` மாற்றம், இடத்திலிருந்து பெறப்பட்ட இயல்புநிலைகள், இரண்டு
களஞ்சியங்கள் (`0x1D` கொண்ட சுற்றுப்பயணமும் வேண்டுமென்றே சேதப்படுத்திய கோப்புகளும் உட்பட), சிம்பாலஜி அட்டவணை, ஸ்கேனர் தள
விதி, பதிப்புத் தண்டு, மற்றும் பட்டியல்களை உள்ளடக்குகின்றன.

மூன்று அறிந்துகொள்ளத் தக்கவை, ஏனெனில் அவை செயல்பாடுகளை அல்லாமல் ஒப்பந்தங்களைப் பாதுகாக்கின்றன:

| சோதனை | எப்போது தோல்வியடைகிறது |
|---|---|
| `CatalogueCoverageTest` | `ui_EN.properties` வரையறுக்காத விசையைக் குறியீடு கேட்கும்போது, அல்லது 35 கோப்புகளில் ஏதேனும் ஆங்கில விசைத் தொகுப்பிலிருந்து விலகும்போது |
| `SymbologiesTest` | JavaPOS அறிவிக்கும் ஏதேனும் `SCAN_SDT_*` மாறிலிக்குக் காட்சிப் பெயர் இல்லாதபோது — JavaPOS மேம்படுத்தல் சேர்ப்பதும் உட்பட |

விசையாகவே காட்டப்படுகிறது — அதனால்தான் சரியாகப் பட்டியல் சோதனை இருக்க வேண்டும்.

**உள்ளடக்கப்படாதவை:** நேரடிக் கருவித்தொகுப்பு தேவைப்படும் எதுவும் — குவிய நடத்தை, முறை நிலைமாற்றி, அட்டவணைத் திருத்தம், மொழி
மாற்றம், மற்றும் [திரெட்டுகள்](#திரெட்டுகள்) கீழ் விவரிக்கப்பட்ட இரண்டு செயலிழப்புகள். அவை உண்மையான சாளரத்தை இயக்கிச்
சரிபார்க்கப்பட்டன, ஆனால் அவற்றில் பின்னடைவு ஏற்பட்டால் கட்டமைப்பு தோல்வியடையாது. TestFX அல்லது Monocle ஐச் சேர்த்தால் அந்த
இடைவெளி மூடப்படும்.

## அறியப்பட்ட வரம்புகளும் மீதமுள்ள பணிகளும்

- **தலையில்லா UI சோதனைகள் இல்லை.** [சோதனை](#சோதனை) பார்க்கவும்.
- **தளம் சார்ந்த கலைப்பொருட்கள்.** இரண்டு பொதியாக்கங்களும் ஒரு தளத்தின் JavaFX நேட்டிவ்களைத் தொகுக்கின்றன; ஒவ்வொரு
  இலக்குக்கும் `-Dfx.platform` உடன் ஒன்றைக் கட்டமையுங்கள் (எந்த இயந்திரமும் அனைத்தையும் கட்டமைக்க முடியும்). எதுவும் Java
  இயக்க நேரத்தைத் தொகுப்பதில்லை — அதற்கு `jpackage` தேவை, அது தான் இயங்கும் OS க்கு மட்டுமே கட்டமைக்கிறது.
- **ஸ்கேனர் உள்ளீடு Windows இல் மட்டுமே.** [தள வாயில்](#தள-வாயில்) பார்க்கவும்.
- **`ScanSource.label()` உள்ளூர்மயமாக்கப்படவில்லை.** [வேண்டுமென்றே
  மொழிபெயர்க்கப்படாதவை](#வேண்டுமென்றே-மொழிபெயர்க்கப்படாதவை) பார்க்கவும்.
- **`UiState.mode` ஒரு `String`** (`"PARSE"` / `"BUILD"`), அதன் அருகிலுள்ள `Theme` ஒரு enum, எனவே அந்த நேரடி பல
  இடங்களில் தோன்றுகிறது. ஒரு enum அவற்றை நீக்கும்.
- **Digital Link இலக்கு களமும் பாதை முன்னொட்டும் மட்டுமே.** `BuilderDigitalLinkConfig` கூடுதல் வினவல் அளவுருக்களையும் ஒரு
  துண்டையும் (fragment) ஆதரிக்கிறது; திருத்தி அவற்றை வெளிப்படுத்துவதில்லை.
- **ஒன்றையொன்று விலக்கும் AI இணைகள் (`GE-S006`) திருத்தியில் குறிக்கப்படுவதில்லை**, தெரியாத மற்றும் நகல் AI கள்
  குறிக்கப்படுவது போல — உருவாக்கம் நேரடியாகத் தோல்வியடைகிறது.
- **மையப் பிழைப் பட்டியல் மேற்கோள் குறிகளை இரட்டிப்பாக்குகிறது** (`value ''09506000134350''`), இது உருவாக்கத் தோல்விகளிலும்
  அறிக்கையிலும் அப்படியே தோன்றுகிறது. இது தப்பிப்பு நீக்கப்படாத `MessageFormat` மேற்கோள்-தப்பிப்பு போலத் தெரிகிறது; திருத்தம்
  மையத்தில் செய்யப்பட வேண்டும்.
