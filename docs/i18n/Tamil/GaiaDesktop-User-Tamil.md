## இது என்ன

GAIA Desktop, GS1 தரவோடு இரண்டு வேலைகளைச் செய்கிறது:

- **பகுப்பாய்வு** — GS1 எலிமெண்ட் சரத்தையோ Digital Link URIயையோ தட்டச்சு செய்யுங்கள்,
  ஒட்டுங்கள், கோப்பிலிருந்து திறங்கள் அல்லது ஸ்கேன் செய்யுங்கள்; முடிவை முழு அறிக்கையாகப்
  படியுங்கள் — ஒவ்வொரு பயன்பாட்டு அடையாளங்காட்டியும் (AI) எதைக் குறிக்கிறது, எது தவறு,
  ஏன் தவறு என்பதுடன்;
- **உருவாக்கம்** — AI / மதிப்பு இணைகளை எலிமெண்ட் சரமாகவோ Digital Link URIயாகவோ சேர்த்து
  அமைத்தல்.

GS1 பற்றி இந்தப் பயன்பாட்டுக்குத் தெரிந்த அனைத்தும் — ஒவ்வொரு AI வரையறை, சரிபார்ப்பு விதி,
பிழைச் செய்தி, மொழியாக்கம் செய்யப்பட்ட விளக்கம் — அடியில் இயங்கும் GAIA இயந்திரத்திலிருந்தே
வருகிறது. பயன்பாடு தன் சொந்த விதிகளைச் சேர்ப்பதில்லை; எனவே அது ஏற்பது இயந்திரம் ஏற்பது
எதுவோ அதுதான்.

## இயக்குதல்

```bash
java -jar gaia-desktop.jar
```

இந்த JAR கோப்புக்கு, அதனுடன் வழங்கப்படும் `lib/` அடைவு தேவை — இரண்டையும் சேர்த்தே
வையுங்கள், இல்லையெனில் பயன்பாடு தொடங்காது. (தனித்து இயங்கும் ஒற்றை JAR ஆகவும் கட்டமைக்கலாம்;
[உருவாக்குநர் வழிகாட்டியைப்](../../GaiaDesktop-Developer.md#packaging) பார்க்கவும்.)

**Java 21 அல்லது அதற்குப் பிந்தையது** நிறுவப்பட்டிருக்க வேண்டும். வெளியீடு ஒரு குறிப்பிட்ட
இயக்க முறைமைக்கும் செயலி கட்டமைப்புக்கும் உரியது; உங்கள் கணினிக்காகக் கட்டமைக்கப்பட்ட JAR
கோப்பையே பயன்படுத்துங்கள்.

சேமிக்கப்பட்ட மொழியை மாற்றாமல், ஒரு குறிப்பிட்ட மொழியில் திறக்க:

```bash
java -jar gaia-desktop.jar --language=FR
```

மதிப்பாக, பட்டியல் குறியீட்டையும் (`FR`, `PCM`, `ARZ`), முழுப் பெயரையும் (`FRENCH`,
`WU-CHINESE`), அல்லது மொழிக் குறிச்சொல்லையும் (`fr`; காண்டோனீஸுக்கு `zh-HK`; எகிப்திய
அரபிக்கு `ar-EG`) தரலாம் — பெரிய/சிறிய எழுத்து வேறுபாடு கருதப்படாது. இந்த மேலெழுதல் அந்த
ஒரு இயக்கத்திற்கு மட்டுமே: உங்கள் சேமித்த மொழி அப்படியே இருக்கும். எனவே சக ஊழியருக்காக
உருவாக்கிய குறுக்குவழி, உங்கள் நகல் திறக்கும் மொழியை மாற்றிவிடாது. பயன்பாட்டுக்கு *உள்ளே*
ஒரு மொழியைத் தேர்ந்தெடுத்தால் அது உண்மையான தேர்வு; வழக்கம்போல் சேமிக்கப்படும். எந்த மொழியையும்
குறிக்காத மதிப்பு புறக்கணிக்கப்பட்டு, கன்சோலில் ஒரு குறிப்பு எழுதப்படும்; பயன்பாடு
தொடங்க மறுக்காமல் சேமித்த மொழியிலேயே திறக்கும்.

தொடங்கும்போது, பயன்பாட்டின் பதிப்பு, அது கட்டமைக்கப்பட்ட தேதி, இயந்திரத்தின் பதிப்பு
ஆகியவற்றைக் கூறும் ஒரு வரியைக் கன்சோல் அச்சிடும். பிழை அறிக்கையில் மேற்கோள் காட்ட வேண்டியது
அந்த வரிதான்.

## சாளரம்

```
┌────────────────────────────────────────────────────────────────────┐
│ menu bar                                                           │
├────────────────────────────────────────────────────────────────────┤
│ [Parse|Build]  … mode-specific controls …   Save report   Options  │
├────────────────────────────────────────────────────────────────────┤
│ input bar (Parse)   or   AI editor (Build)                         │
├──────────────────┬─────────────────────────────────────────────────┤
│ Captures         │ Parse report                    │ Options       │
│ (newest first)   │                                 │ panel         │
├──────────────────┴─────────────────────────────────────────────────┤
│ status …                                     scanner: off  [About] │
└────────────────────────────────────────────────────────────────────┘
```

> இந்த ஆவணத்தின் மற்ற குறியீட்டுத் தொகுதிகளைப் போலவே, இந்த வரைபடமும் ஆங்கிலத்திலேயே
> இருக்கிறது. திரையில் நீங்கள் காண்பது: *பகுப்பாய்வு* / *உருவாக்கம்*, *பதிவுகள்*,
> *அறிக்கையைச் சேமி*, *விருப்பங்கள்*, *ஸ்கேனர்: அணைப்பு*, *பற்றி*.

**macOS மற்றும் Linux இல், இந்த வரைபடத்தில் உள்ள ஸ்கேனர் வரிசை இருக்காது** — கருவிப்
பட்டையில் நிலைமாற்றியோ சாதனத் தேர்வோ இல்லை, *ஸ்கேனர்* பட்டியும் இல்லை, நிலைப் பட்டையில்
*ஸ்கேனர்: அணைப்பு* என்பதும் இல்லை. [ஸ்கேன் செய்தலைப்](#ஸ்கேன்-செய்தல்) பார்க்கவும்.

**பகுப்பாய்வு ⇄ உருவாக்கம்** மாற்றி, கருவிப் பட்டைக்குக் கீழுள்ள பகுதியையும் பதிவு தொடர்பான
கட்டுப்பாடுகளையும் மட்டுமே மாற்றுகிறது. வரலாறு, அறிக்கை, விருப்பப் பலகம், ஏற்றுமதிச் செயல்கள்
ஆகியவை இரு முறைகளுக்கும் பொதுவானவை; ஏனெனில் வெற்றிகரமான உருவாக்கம் இன்னொரு பதிவாகவே மாறுகிறது.

விருப்பப் பலகம் **முதல் தொடக்கத்தில் மூடியே** இருக்கும். முறை, பலகத்தின் தெரிவுநிலை, தோற்றம்,
கடைசியாகப் பயன்படுத்திய ஸ்கேனர் ஆகியவை அடுத்த இயக்கத்திலும் நினைவில் இருக்கும்.

## பகுப்பாய்வு முறை

### உள்ளீட்டுப் பட்டையும் {GS} டோக்கனும்

இந்தப் பட்டை, எலிமெண்ட் சரத்தையும், GS1 Digital Link URIயையும், AIM Code ID முன்னொட்டுடன்
(`]d2…`) கூடிய மூல ஸ்கேனையும் ஏற்கும். <kbd>Enter</kbd> பகுப்பாய்வைத் தொடங்கும்.

மாறும் நீள AIகள் **FNC1** — கண்ணுக்குத் தெரியாத கட்டுப்பாட்டு எழுத்து `0x1D` — ஆல்
பிரிக்கப்படுகின்றன. உரைப் புலம் அந்த எழுத்தை வைத்திருக்க முடியாது: அது அமைதியாக விழுங்கப்படும்;
`01…` + FNC1 + `10LOT` என்பது `01…10LOT` ஆக வந்து சேரும் — வேறு பொருள் தரும் எலிமெண்ட் சரமாக.

எனவே பயன்பாடு, பிரிப்பானைக் கண்ணுக்குத் தெரியும் **`{GS}`** டோக்கனாகக் காட்டி,
பகுப்பாய்விக்குச் செல்லும் வழியில் மீண்டும் மாற்றுகிறது:

- **`{GS}` பொத்தான்** நிலைக்குறி உள்ள இடத்தில் டோக்கனைச் செருகும்;
- உண்மையான பிரிப்பான் எழுத்துகளை **ஒட்டும்போது** — விசைப்பலகை, சூழல் பட்டி, இழுத்து விடுதல்
  எதுவாயினும் — அவை தானாக `{GS}` ஆக மாறும்; எதுவும் இழக்கப்படுவதில்லை;
- அறிக்கை எழுதும் அதே முறையில்தான் டோக்கனும் எழுதப்படுகிறது; எனவே அறிக்கையிலிருந்து நகலெடுத்த
  மதிப்பை நேரடியாக மீண்டும் ஒட்டலாம்.

பதிவு, அறிக்கை, சேமிக்கப்பட்ட வரலாறு — மூன்றும் **உண்மையான** பிரிப்பானையே கொண்டுள்ளன.
டோக்கன் என்பது நீங்கள் காண்பதும் தட்டச்சு செய்வதும் மட்டுமே.

### ஸ்கேன் செய்தல்

> **Windows மட்டும்.** Zebra தன் ஸ்கேனர் இயக்கிகளை Windowsக்கு மட்டுமே வழங்குகிறது; எனவே
> macOS மற்றும் Linux இல் பயன்பாடு எந்த ஸ்கேனர் கட்டுப்பாட்டையும் உருவாக்குவதில்லை —
> *ஸ்கேனரை இணை* நிலைமாற்றி இல்லை, சாதனத் தேர்வு இல்லை, *ஸ்கேனர்* பட்டி இல்லை, நிலைப்
> பட்டையில் ஸ்கேனர் நிலையும் இல்லை. எதுவும் மங்கலாக்கப்படவில்லை; ஏனெனில் அதை இயக்கக்கூடிய
> அமைப்போ சாதனமோ இல்லை. சேமித்த ஸ்கேன்களைக் கொண்ட கோப்பைத் திறப்பது உட்பட மற்ற அனைத்தும்
> எல்லா இயங்குதளங்களிலும் வேலை செய்யும்.

*ஸ்கேனரை இணை* என்பது தேர்வுப் பட்டியலில் குறிப்பிட்ட சாதனத்தைத் திறக்கும்;
`ZebraAllScanners` இயல்புநிலை மதிப்பு, பெரும்பாலான மாதிரிகளுக்குப் பொருந்தும். ஒவ்வொரு
ஸ்கேனும் பகுக்கப்பட்டு, தானாக வரலாற்றில் சேர்க்கப்படும்.

ஸ்கேனர் தரவு பைட் வாரியாகப் படிக்கப்படுகிறது; எனவே AIM Code ID முன்னொட்டும் ஒவ்வொரு FNC1
பிரிப்பானும், ஸ்கேனர் அனுப்பியபடியே பகுப்பாய்விக்குச் சென்று சேரும்.

உருவாக்க முறையில் ஸ்கேனர் கட்டுப்பாடுகள் மறைக்கப்படும்; ஆனால் இணைக்கப்பட்ட ஸ்கேனர் தொடர்ந்து
வேலை செய்யும்: *ஸ்கேனர் → இணை / துண்டி* (<kbd>⌘K</kbd>) இன்னும் நிலைமாற்றும், நிலைப் பட்டை
இன்னும் அறிவிக்கும், திருத்தி திறந்திருக்கும்போது வரும் ஸ்கேனும் பதிவு செய்யப்படும்.

ஒரு சாதனம் இணையவில்லை என்றால், [சிக்கல் தீர்வைப்](#சிக்கல்-தீர்வு) பார்க்கவும்.

### கோப்பைத் திறத்தல்

*கோப்பு → உரைக் கோப்பைத் திற…* என்பது **காலியாக இல்லாத ஒவ்வொரு வரியையும் தனிப் பதிவாக**
பகுக்கும்; யாரோ அனுப்பிய ஸ்கேன்களின் தொகுப்பைச் சட்டெனச் செயலாக்க இதுவே வழி. கோப்பு பைட்
வாரியாகப் படிக்கப்படுவதால், அதனுள் இருக்கும் மூலப் பிரிப்பான்களும் தப்பிப் பிழைக்கும்.

### பதிவு வரலாறு

புதியவை முதலில். ஒவ்வொரு வரியிலும் செல்லுபடி / செல்லாத புள்ளி, ஒரு வரிச் சுருக்கம், பதிவு
நேரம், அது வந்த இடம், அதிலுள்ள AIகளின் எண்ணிக்கை ஆகியவை காட்டப்படும். முந்தைய நாளின்
பதிவுகளுக்கு மட்டுமே தேதி தோன்றும் — இன்றைய வரிகளில் நேரம் மட்டும்.

சுருக்கம் என்பது Digital Linkக்கு **Digital Link URI**, மற்றவற்றுக்கு **HRI**: ஓர்
எலிமெண்ட் சரத்திற்கு `(01)09506000134352 (17)261231` என்பது
`01095060001343521726123110…` ஐ விடப் படிக்க எளிது.

ஒரு பதிவின் மேல் வலது சொடுக்கு செய்தால், அதன் உள்ளீட்டையோ HRIயையோ நகலெடுக்கலாம், உள்ளீட்டுப்
பட்டைக்குத் திருப்பி அனுப்பலாம், திருத்தியில் திறக்கலாம், நீக்கலாம், அல்லது வரலாற்றை அழிக்கலாம்.

## உருவாக்க முறை

### AI திருத்தி

AI / மதிப்பு இணைகளின் அட்டவணை. AI குறியீட்டைத் தட்டச்சு செய்யுங்கள், அல்லது *AI சேர்…*
பட்டியலிலிருந்து **இயந்திரம் அறிந்த ஒவ்வொரு AIயையும்** தேர்ந்தெடுங்கள்; தட்டச்சு செய்யும்
போதே **தலைப்பு**, **வடிவம்**, **விளக்கம்** நெடுவரிசைகள் நீங்கள் தேர்ந்த மொழியில் நிரம்பும்.
உருவாக்கி மறுக்கக்கூடிய AIயை இந்தத் தேர்வுப் பட்டியல் காட்டாது.

அட்டவணையின் இறுதியில் எப்போதும் **ஒரு காலி வரிசை** இருக்கும்: அதில் தட்டச்சு செய்தால் அடுத்தது
தோன்றும். எனவே பல AIகள் கொண்ட சரத்திற்கு *வரிசை சேர்* தேவைப்படுவதே இல்லை.

திருத்துதல், அட்டவணை எப்படி நடந்துகொள்ள வேண்டுமோ அப்படியே நடக்கும்: <kbd>Enter</kbd>,
<kbd>Tab</kbd>, <kbd>Shift</kbd>+<kbd>Tab</kbd>, வெளியே சொடுக்குதல் — அனைத்தும் நீங்கள்
தட்டச்சு செய்ததை **வைத்துக்கொள்ளும்**; <kbd>Esc</kbd> கைவிடும். <kbd>Tab</kbd> என்பது
AI → மதிப்பு → அடுத்த வரிசை என நகரும், திருத்த முடியாத நெடுவரிசைகளைத் தவிர்த்து.

### திருத்தி மறுப்பவை

| | என்ன நடக்கும் |
|---|---|
| இயந்திரம் அறியாத AI | தட்டச்சு செய்யும்போதே வரிசை சிவப்பாகும்; உருவாக்கம் விளக்கத்துடன் மறுக்கப்படும் |
| தேர்வுப் பட்டியலிலிருந்து அதே AI இரண்டாம் முறை | சேர்க்கப்படாது — ஒரு செய்தி அதைக் குறிப்பிடும், ஏற்கெனவே அதைக் கொண்ட வரிசை தேர்ந்தெடுக்கப்படும் |
| கையால் தட்டச்சு செய்து அதே AI இரண்டாம் முறை | இரு வரிசைகளும் குறிக்கப்படும்; உருவாக்கம் `GE-S004` பிழையுடன் மறுக்கப்படும் |
| உருவாக்க எதுவும் இல்லை | ஒரு செய்தி; பதிவு எதுவும் உருவாக்கப்படாது |

ஓர் எலிமெண்ட் சரத்தில் ஓர் AI ஒரு முறை மட்டுமே வர முடியும்; அதனால்தான் தோல்வி உறுதியான
உருவாக்கத்தை முயலவிடாமல், தேர்வுப் பட்டியல் உடனேயே மறுக்கிறது.

### எலிமெண்ட் சரமா, Digital Link கா

**எலிமெண்ட் சரத்தை உருவாக்கு** என்பது, தரநிலை கோரும் இடங்களில் FNC1 பிரிப்பானைச் செருகி
வரிசைகளை இணைக்கும். **Digital Link உருவாக்கு** ஒரு URIயை உருவாக்கும்; நியமமான `id.gs1.org`
க்குப் பதிலாக உங்கள் சொந்தத் தீர்விக்கு அதைத் திருப்ப *Digital Link இலக்கு* என்பதை
விரிவாக்குங்கள்:

| புலம் | விளைவு | காலியாக இருந்தால் |
|---|---|---|
| டொமைன் | தீர்வியின் புரவலன், எ.கா. `example.com` | `id.gs1.org` |
| பாதை முன்னொட்டு | AI பாதைக்கு முன் ஒரு பகுதி, எ.கா. `/products` | முன்னொட்டு இல்லை |

**வெற்றி** பெற்றால், முடிவு ஒரு ஸ்கேனைப் போலவே நடத்தப்படும்: பகுக்கப்பட்டு, வரலாற்றில்
சேர்க்கப்பட்டு, அறிக்கையாக வழங்கப்பட்டு, சேமிக்கப்படும். உருவாக்கி தன் சொந்த வெளியீட்டைப்
பகுத்தே சரிபார்க்கிறது; எனவே அது திருப்பித் தருவது நிச்சயம் செல்லுபடியாகும்.

**தோல்வி** அடைந்தால் எதுவும் பதிவு செய்யப்படாது. காரணம் உருவாக்கப் பொத்தான்களுக்குக் கீழ்
இருக்கும் — ஒரு சிக்கலுக்கு ஒரு வரி, ஒவ்வொன்றும் பிழையையும், அது சார்ந்த AIயையும்,
இயந்திரத்தின் சொந்த விளக்கத்தையும் குறிப்பிடும்:

```
GE-C003  (01)  Check digit validation failed for AI (01) value ''09506000134350''
```

> அந்தச் செய்தியில் இரட்டிப்பான மேற்கோள் குறிகள் இந்தப் பயன்பாட்டிலிருந்து அல்ல,
> இயந்திரத்தின் பிழைப் பட்டியலிலிருந்து வருகின்றன.

### ஏற்கெனவே உள்ள பதிவைத் திருத்துதல்

ஒரு பதிவின் மேல் வலது சொடுக்கு → **உருவாக்கம்** என்பது அதன் AIகளைத் திருத்தியில் ஏற்றும்.
ஒரு மதிப்பை மாற்றி மீண்டும் உருவாக்குங்கள்; முடிவு புதிய பதிவாக வந்து சேரும் — மூலப் பதிவு
அப்படியே இருக்கும்.

## அறிக்கை

தேர்ந்தெடுக்கப்பட்ட பதிவு முழு அறிக்கையாக வழங்கப்படுகிறது: தீர்ப்புத் தலைப்புப் பட்டை,
பெயரிடப்பட்ட “நாடா”வாகப் பிரிக்கப்பட்ட எலிமெண்ட் சரம், பகுப்பாய்வு மேனிலைத் தரவு, ஒவ்வொரு
AIக்கும் ஒரு அட்டை அதன் விளக்கங்களுடன், மற்றும் சரிசெய்வதற்கான வழிகாட்டலுடன் கூடிய பிழைகளும்
எச்சரிக்கைகளும்.

**Digital Link** ஆக இருந்தால், ஒவ்வொரு AI அட்டையும் அதன் அமைப்புசார் பங்கையும் சுமக்கும் —
**முதன்மைச் சாவி**, **சாவி தகுதிப்படுத்தி**, அல்லது **தரவுப் பண்பு** — URIயில் அவை தோன்றும்
வரிசைப்படி நிறமிடப்பட்டு. இந்தப் பங்குகள் Digital Linkக்கு மட்டுமே காட்டப்படும்; வெறும்
எலிமெண்ட் சரத்தில் ஓர் AIக்கு URI நிலை என்பதே இல்லை.

அறிக்கை நீங்கள் தேர்ந்த மொழியையும் தோற்றத்தையும் பின்பற்றும்.

### ஏற்றுமதி

| | |
|---|---|
| **அறிக்கையைச் சேமி → HTML ஆக…** (<kbd>⌘S</kbd>) | திரையில் உள்ளதை அப்படியே எழுதும்: எந்த உலாவியிலும் திறக்கும் தன்னிறைவான ஒரு கோப்பு |
| **அறிக்கையைச் சேமி → PDF ஆக…** (<kbd>⌘P</kbd>) | உங்கள் கணினியின் அச்சு உரையாடல் வழியாக அச்சிடும் — அங்கே PDF இலக்கைத் தேர்ந்தெடுங்கள் |

இலக்கும் கோப்புப் பெயரும் தேர்ந்தெடுக்கப்படும் இடம் அச்சு உரையாடல்தான்; அதனால்தான் PDF
அதன் வழியே செல்கிறது: macOS இல் **PDF ▾ → PDF ஆகச் சேமி**, Windows இல் **Microsoft Print
to PDF**, Linux இல் **கோப்புக்கு அச்சிடு**. பக்கங்கள் பிரிக்கப்படும், உரை தேர்ந்தெடுக்கக்
கூடியதாகவே இருக்கும்.

அச்சு மற்றும் PDF வெளியீடு, பயன்பாடு இருண்ட தோற்றத்தில் இருந்தாலும் எப்போதும் வெளிர் வண்ணத்
தட்டையே பயன்படுத்தும்; வண்ண AI சில்லுகளையும் தீர்ப்புப் பட்டையையும் அப்படியே வைத்திருக்கும்.

உங்கள் கணினியில் அச்சுப்பொறியோ PDF இலக்கோ அமைக்கப்படவில்லை என்றால், பயன்பாடு அதைத் தெரிவித்து,
HTML ஏற்றுமதியை நோக்கி வழிகாட்டும் — அதை எந்த உலாவியிலிருந்தும் அச்சிடலாம்.

## பகுப்பாய்வு விருப்பங்கள்

வலதுபுறப் பலகத்தில் இயந்திரத்தின் விருப்பங்கள் அனைத்தும் உள்ளன. எதை மாற்றினாலும்
**தேர்ந்தெடுக்கப்பட்ட பதிவு உடனடியாக மீண்டும் பகுக்கப்படும்**; எனவே இது அடுத்த ஸ்கேனை மட்டும்
பாதிக்கும் அமைப்பு அல்ல — “இந்த அமைப்புகளில் இந்த உள்ளீடு எப்படித் தெரியும்?” எனக் கேட்கும்
கருவியாகவும் இருக்கிறது.

| விருப்பம் | மதிப்புகள் |
|---|---|
| பகுப்பாய்வு முறை | `SYNTAX`, `CONTENT`, `DATA_CARRIER`, `INTERPRETATION` — எவ்வளவு ஆழமாகப் பகுப்பது |
| மொழி | 35 செய்திப் பட்டியல்கள் |
| வரிசை | `LITTLE` (dd/mm/yyyy), `MIDDLE` (mm/dd/yyyy), `BIG` (yyyy/mm/dd) |
| பிரிப்பான் | `SLASH`, `HYPHEN`, `PERIOD` |
| மாதம் | `TWO_DIGIT` (12), `THREE_LETTER` (DEC) |
| ஆண்டு | `FOUR_DIGIT` (2026), `TWO_DIGIT` (26) |
| "requires" சோதனையைத் தவிர் | தேவையான துணை AI இல்லாவிட்டாலும் நிராகரிப்பதை நிறுத்தும் (`GE-S005`) |
| "excludes" சோதனையைத் தவிர் | தரநிலை தடுக்கும் AI இணைகளை நிராகரிப்பதை நிறுத்தும் (`GE-S006`) |

பலகத்தின் அடிப்பகுதியில் உள்ள *இயல்புநிலைக்கு மீட்டமை*, இயந்திரத்தின் சொந்த இயல்பு
மதிப்புகளை மீட்டெடுக்கும்.

### முதல் தொடக்கம்

இன்னும் எதுவும் சேமிக்கப்படாத நிலையில், பயன்பாடு இயந்திரத்தின் இயல்பு மதிப்புகளைப் பயன்படுத்தாமல்
**உங்கள் கணினியின் பிராந்திய அமைப்புகளிலிருந்து** தன் அமைப்புகளை எடுக்கும்:

- **மொழி** உங்கள் கணினியின் இருப்பிடத்திலிருந்து வரும்; அதற்குப் பட்டியல் இல்லையெனில்
  ஆங்கிலத்திற்குத் திரும்பும்;
- **தேதி விருப்பங்கள்** உங்கள் இருப்பிடத்தின் சுருக்கத் தேதி வடிவத்திலிருந்து படிக்கப்படும் —
  கூறுகளின் வரிசை, பிரிப்பான், மாதமும் ஆண்டும் சுருக்கப்படுகின்றனவா என்பது.

> **குறிப்பு.** எனவே சுருக்கத் தேதியை இரு இலக்க ஆண்டுடன் எழுதும் இருப்பிடம், இங்கேயும் இரு
> இலக்க ஆண்டுடனே தொடங்கும். இது உங்கள் கணினியின் மற்ற இடங்களுடன் ஒத்துப்போகும், ஆனால்
> இயந்திரத்தின் சொந்த இயல்பான நான்கு இலக்கத்திலிருந்து மாறுபடும். பலகத்தில் அதை மாற்றினால்
> அந்தத் தேர்வு நிலைத்திருக்கும்.

## மொழிகள்

ஒரு மொழியைத் தேர்ந்தெடுத்தால் பிழைச் செய்திகள் மட்டுமல்ல, **பயன்பாடு முழுவதுமே** மாறும் —
பட்டிகள், பொத்தான்கள், திருத்தி, விருப்பப் பலகம், நிலை வரி, அறிக்கை. வலமிருந்து இடமாக எழுதப்படும்
மொழிகளில் சாளரமும் அறிக்கையும் திரும்பும்.

35 மொழிகளும் கிடைக்கின்றன; இரு அடுக்கு பரவலுடன்:

| | பரவல் |
|---|---|
| பகுப்பாய்வு அறிக்கைகளும் இயந்திரப் பிழைச் செய்திகளும் | **35 மொழிகளும்** |
| பயன்பாட்டின் சொந்தப் பட்டிகள், பொத்தான்கள், பெயர்கள் | **35 மொழிகளும்** |

வலமிருந்து இடமாக எழுதப்படும் மொழிகள் — அரபு, எகிப்திய அரபு, பாரசீகம், உருது — பயன்பாடு
திறந்த கணத்திலிருந்தே சாளரத்தையும் அறிக்கையையும் திருப்புகின்றன.

மொழி ஒவ்வோர் இயக்கத்திலும் நினைவில் வைக்கப்படும். ஒரே ஒரு முறை வேறு மொழியில் திறக்க,
[`--language`](#இயக்குதல்) ஐப் பார்க்கவும்.

சில விஷயங்கள் எல்லா மொழிகளிலும் வேண்டுமென்றே மொழிபெயர்க்கப்படுவதில்லை: மூல மதிப்புகளுக்கு
அருகில் அச்சிடப்படும் சுருக்கப் புலப் பெயர்கள் (`format`, `position`, `raw`, `len` …) —
அவை சொற்கள் அல்ல, அடையாளங்காட்டிகள்; மாதிரி உள்ளீட்டுப் பெயர்களும் குறியீட்டு முறைப்
பெயர்களும் — அவை GS1 மற்றும் தொழில்துறைச் சொற்கள்; மேலும் ஒரு நீண்ட தரநிலைப் பத்தி — அங்கே
பாதி மொழிபெயர்ப்பு தவறாக வழிநடத்தும்.

## நினைவில் வைக்கப்படுவது

உங்கள் இல்ல அடைவுக்குள் `.gaia-desktop` இல் இரண்டு கோப்புகள்:

| கோப்பு | உள்ளடக்கம் |
|---|---|
| `options.properties` | ஒவ்வொரு பகுப்பாய்வு விருப்பமும், தோற்றம், விருப்பப் பலகம் திறந்திருக்கிறதா, கடைசி ஸ்கேனர், சாளரம் விடப்பட்ட முறை |
| `captures.tsv` | பதிவு வரலாறு, புதியவை முதலில், அதிகபட்சம் 500 உள்ளீடுகள் |

விருப்பங்கள் நீங்கள் மாற்றும் ஒவ்வொரு முறையும் எழுதப்படும்; வரலாறு அது மாறும் ஒவ்வொரு
முறையும். இரண்டும் வெளியேறும்போது மீண்டும் எழுதப்படும்.

இரண்டில் ஒன்றை நீக்கினால் அந்தப் பகுதி மட்டுமே மீட்டமைக்கப்படும், வேறெதுவும் இல்லை — சிதைந்த
வரலாறு உங்கள் அமைப்புகளைப் பறிக்கக் கூடாது என்பதற்காகவே இரண்டும் தனித்தனியாக வைக்கப்பட்டுள்ளன.
கையால் திருத்திச் சிதைந்த கோப்பும் கொடியதல்ல: ஒவ்வோர் அமைப்பும் தனித்தனியே இயல்பு மதிப்புக்குத்
திரும்பும்; எனவே ஒரு தவறான வரி அந்த வரியை மட்டுமே செலவழிக்கும்.

வரலாறு சேமிப்பது உள்ளீட்டையே, பகுப்பாய்வை அல்ல. ஏற்றும்போது அது மீண்டும் பகுக்கப்படுகிறது;
அதாவது மீட்டெடுக்கப்பட்ட பதிவு, பதிவு செய்யப்பட்ட அன்றைய விருப்பங்களை அல்ல, **இப்போதைய**
விருப்பங்களையே பிரதிபலிக்கும்.

## வரம்புகள்

- **ஸ்கேன் செய்தல் Windows இல் மட்டுமே** — இயக்கிகள் அப்படி இருப்பதால்.
- **PDF, சேமிப்பு உரையாடல் அல்ல, அச்சு உரையாடல் வழியே** செல்கிறது.
- **Digital Link இலக்குகள் டொமைனையும் பாதை முன்னொட்டையும் மட்டுமே** ஏற்கும்; கூடுதல் வினவல்
  அளவுருக்களையோ துண்டையோ அல்ல.
- **ஓர் AI ஒரு முறை மட்டுமே** ஓர் எலிமெண்ட் சரத்தில் வர முடியும் — இது பயன்பாட்டின் வரம்பு
  அல்ல, GS1 விதி.
