## 무엇인가

GAIA Desktop은 GS1 데이터로 두 가지 일을 합니다.

- **파싱** — GS1 요소 문자열이나 Digital Link URI를 입력하거나 붙여넣거나 파일에서 열거나
  스캔한 뒤, 그 결과를 완전한 보고서로 읽습니다. 각 응용 식별자(AI)가 무엇을 뜻하는지, 무엇이
  잘못되었는지, 왜 그런지를 알 수 있습니다.
- **생성** — AI와 값의 쌍을 모아 요소 문자열이나 Digital Link URI로 조립합니다.

이 애플리케이션이 GS1에 대해 아는 모든 것 — 모든 AI 정의, 모든 검증 규칙, 모든 오류 메시지,
모든 현지화된 설명 — 은 그 아래에 있는 GAIA 엔진에서 옵니다. 애플리케이션은 자체 규칙을 더하지
않으므로, 애플리케이션이 받아들이는 것은 엔진이 받아들이는 것과 정확히 같습니다.

## 실행하기

```bash
java -jar gaia-desktop.jar
```

이 JAR 파일에는 함께 배포되는 `lib/` 디렉터리가 필요합니다. 둘을 함께 두십시오. 떨어뜨리면
애플리케이션이 시작되지 않습니다. (단독으로 완결된 JAR 파일을 빌드할 수도 있습니다.
[개발자 안내서](../../GaiaDesktop-Developer.md#packaging)를 참조하십시오.)

**Java 21 이상**이 설치되어 있어야 합니다. 배포본은 운영 체제와 프로세서 아키텍처마다 다르므로,
사용하는 컴퓨터에 맞게 빌드된 JAR 파일을 사용하십시오.

저장된 언어를 바꾸지 않고 특정 언어로 열려면 다음과 같이 실행합니다.

```bash
java -jar gaia-desktop.jar --language=FR
```

값으로는 카탈로그 코드(`FR`, `PCM`, `ARZ`), 전체 이름(`FRENCH`, `WU-CHINESE`), 또는 언어
태그(`fr`, 광둥어는 `zh-HK`, 이집트 아랍어는 `ar-EG`)를 쓸 수 있으며 대소문자는 가리지 않습니다.
이 지정은 해당 실행에만 적용됩니다. 저장된 언어는 그대로 남으므로, 동료를 위해 만든 바로 가기가
자신의 사본이 열리는 언어를 바꾸는 일은 없습니다. 애플리케이션 *안에서* 언어를 고르는 것은 실제
선택으로 간주되어 평소처럼 저장됩니다. 어떤 언어도 가리키지 않는 값은 콘솔에 기록을 남기고
무시되며, 실행을 거부하는 대신 저장된 언어로 열립니다.

시작할 때 콘솔에는 애플리케이션 버전, 빌드 날짜, 엔진 버전을 담은 한 줄이 출력됩니다. 결함을
보고할 때 인용해야 할 것이 바로 그 줄입니다.

## 창

```
┌────────────────────────────────────────────────────────────────────┐
│ menu bar                                                           │
├────────────────────────────────────────────────────────────────────┤
│ [Parse|Build]  … mode-specific controls …   Save report   Options  │
├────────────────────────────────────────────────────────────────────┤
│ input bar (Parse)   or   AI editor (Build)                         │
├──────────────────┬─────────────────────────────────────────────────┤
│ Captures         │ Parse report                    │ Options       │
│ (newest first)   │                                 │ panel         │
├──────────────────┴─────────────────────────────────────────────────┤
│ status …                                     scanner: off  [About] │
└────────────────────────────────────────────────────────────────────┘
```

> 이 문서의 다른 코드 블록과 마찬가지로, 위 그림도 영어 표기를 그대로 둡니다. 화면에서는
> *파싱* / *생성*, *캡처*, *보고서 저장*, *옵션*, *스캐너: 꺼짐*, *정보* 로 표시됩니다.

**macOS와 Linux에서는 그림 속 스캐너 관련 부분이 아예 없습니다.** 도구 모음에 토글도 장치
선택도 없고, *스캐너* 메뉴도 없으며, 상태 표시줄에 *스캐너: 꺼짐* 도 나타나지 않습니다.
[스캔](#스캔)을 참조하십시오.

**파싱 ⇄ 생성** 전환은 도구 모음 아래의 띠와 캡처 관련 컨트롤만 바꿉니다. 기록, 보고서, 옵션
패널, 내보내기 동작은 두 모드 모두에서 쓰입니다. 생성이 성공하면 그것은 그저 또 하나의 캡처가
되기 때문입니다.

옵션 패널은 **첫 실행 시 닫혀 있습니다**. 모드, 패널 표시 여부, 테마, 마지막으로 사용한 스캐너는
실행과 실행 사이에 기억됩니다.

## 파싱 모드

### 입력창과 {GS} 토큰

입력창은 요소 문자열, GS1 Digital Link URI, 또는 AIM Code ID 접두사(`]d2…`)가 붙은 원시 스캔
데이터를 받습니다. <kbd>Enter</kbd> 키로 파싱합니다.

가변 길이 AI는 **FNC1** — 눈에 보이지 않는 제어 문자 `0x1D` — 로 구분됩니다. 텍스트 필드는 이
문자를 담을 수 없습니다. 조용히 삼켜지기 때문에 `01…` + FNC1 + `10LOT` 은 `01…10LOT` 으로 도착
하고, 이는 뜻이 달라진 요소 문자열입니다.

그래서 애플리케이션은 구분자를 눈에 보이는 토큰 **`{GS}`** 로 표시하고, 파서로 보내는 길에 다시
되돌립니다.

- **`{GS}` 버튼**은 커서 위치에 토큰을 삽입합니다.
- 진짜 구분 문자를 **붙여넣으면** — 키보드로든, 상황에 맞는 메뉴로든, 끌어다 놓기로든 — 자동으로
  `{GS}` 로 바뀌므로 아무것도 잃지 않습니다.
- 토큰을 적는 방식은 보고서가 적는 방식과 같으므로, 보고서에서 복사한 값을 그대로 다시 붙여넣을
  수 있습니다.

캡처, 보고서, 저장된 기록에는 모두 **진짜** 구분자가 들어 있습니다. 토큰은 보고 입력하는
형태일 뿐입니다.

### 스캔

> **Windows 전용.** Zebra는 스캐너 드라이버를 Windows용으로만 제공하므로, macOS와 Linux에서는
> 애플리케이션이 스캐너 관련 컨트롤을 아예 만들지 않습니다. *스캐너 연결* 토글도, 장치 선택도,
> *스캐너* 메뉴도, 상태 표시줄의 스캐너 상태도 없습니다. 흐리게 표시된 것이 아니라 처음부터
> 없습니다. 그것을 켤 수 있는 설정이나 장치가 존재하지 않기 때문입니다. 저장된 스캔이 담긴
> 파일을 여는 것을 포함해 나머지 기능은 어느 환경에서나 동작합니다.

*스캐너 연결*은 선택 목록에 지정된 장치를 엽니다. 기본값 `ZebraAllScanners` 는 대부분의 모델에
맞습니다. 스캔할 때마다 파싱되어 자동으로 기록에 추가됩니다.

스캐너 데이터는 바이트 단위로 읽히므로, AIM Code ID 접두사와 모든 FNC1 구분자가 스캐너가 보낸
그대로 파서에 도달합니다.

생성 모드에서는 스캐너 컨트롤이 숨겨지지만, 연결된 스캐너는 계속 동작합니다.
*스캐너 → 연결 / 연결 해제*(<kbd>⌘K</kbd>)로 여전히 전환할 수 있고, 상태 표시줄도 계속 알려
주며, 편집기가 열려 있는 동안 들어온 스캔도 그대로 캡처됩니다.

장치가 연결되지 않으면 [문제 해결](#문제-해결)을 참조하십시오.

### 파일 열기

*파일 → 텍스트 파일 열기…* 는 **비어 있지 않은 각 줄을 하나의 캡처로** 파싱합니다. 누군가 보내온
스캔 묶음을 빠르게 처리하는 방법입니다. 파일은 바이트 단위로 읽히므로 그 안의 원시 구분자도
그대로 살아남습니다.

### 캡처 기록

최신 항목이 위에 옵니다. 각 행에는 유효 / 무효를 나타내는 점, 한 줄 요약, 그리고 캡처 시각,
출처, 포함된 AI 개수가 표시됩니다. 날짜는 이전 날짜의 캡처에만 나타나고, 오늘의 행에는 시각만
표시됩니다.

요약은 Digital Link의 경우 **Digital Link URI**, 그 밖의 경우 **HRI** 입니다. 요소 문자열이라면
`(01)09506000134352 (17)261231` 쪽이 `01095060001343521726123110…` 보다 읽기 쉽기 때문입니다.

캡처를 오른쪽 클릭하면 입력이나 HRI를 복사하고, 입력창으로 되돌리고, 편집기에서 열고, 삭제하거나
기록을 지울 수 있습니다.

## 생성 모드

### AI 편집기

AI와 값 쌍으로 이루어진 표입니다. AI 코드를 직접 입력하거나 *AI 추가…* 목록에서 **엔진이 아는
모든 AI** 중에서 고를 수 있습니다. 입력하는 동안 **제목**, **형식**, **설명** 열이 선택한 언어로
채워집니다. 이 목록은 생성 단계에서 거부될 AI를 제시하지 않습니다.

표의 끝에는 항상 **빈 행이 하나** 남아 있습니다. 거기에 입력하면 다음 행이 나타나므로, 여러 AI가
들어가는 문자열에도 *행 추가* 가 필요하지 않습니다.

편집 동작은 표가 마땅히 그래야 하는 방식대로입니다. <kbd>Enter</kbd>, <kbd>Tab</kbd>,
<kbd>Shift</kbd>+<kbd>Tab</kbd>, 그리고 바깥을 클릭하는 것 모두 입력한 내용을 **유지**합니다.
<kbd>Esc</kbd> 는 버립니다. <kbd>Tab</kbd> 은 AI → 값 → 다음 행 순으로 이동하며, 편집할 수 없는
열은 건너뜁니다.

### 편집기가 거부하는 것

| | 어떻게 되는가 |
|---|---|
| 엔진이 인식하지 못하는 AI | 입력하는 동안 해당 행이 빨갛게 바뀌고, 생성은 설명과 함께 거부됩니다 |
| 목록에서 같은 AI를 두 번 | 추가되지 않습니다. 메시지가 해당 AI를 알려 주고, 이미 그것을 가진 행이 선택됩니다 |
| 손으로 같은 AI를 두 번 입력 | 두 행 모두 표시되고, 생성은 오류 `GE-S004` 로 거부됩니다 |
| 생성할 것이 없음 | 메시지가 표시되고, 캡처는 만들어지지 않습니다 |

하나의 요소 문자열에서 같은 AI는 한 번만 나타날 수 있습니다. 그래서 목록은 실패가 뻔한 생성을
시도하게 두는 대신 그 자리에서 거부합니다.

### 요소 문자열 또는 Digital Link

**요소 문자열 생성** 은 표준이 요구하는 자리마다 FNC1 구분자를 넣으며 각 행을 조립합니다.
**Digital Link 생성** 은 URI를 만듭니다. 표준인 `id.gs1.org` 대신 자체 리졸버로 향하게 하려면
*Digital Link 대상* 을 펼치십시오.

| 항목 | 효과 | 비워 두면 |
|---|---|---|
| 도메인 | 리졸버 호스트, 예: `example.com` | `id.gs1.org` |
| 경로 접두사 | AI 경로 앞에 오는 한 구간, 예: `/products` | 접두사 없음 |

**성공** 하면 결과는 스캔과 똑같이 다루어집니다. 파싱되고, 기록에 추가되고, 보고서로 그려지고,
저장됩니다. 생성은 자신의 출력을 직접 파싱해 검증하므로, 돌려주는 결과는 반드시 유효합니다.

**실패** 하면 아무것도 캡처되지 않습니다. 이유는 생성 버튼 아래에 남으며, 문제마다 한 줄씩 오류,
해당 AI, 그리고 엔진 자신의 설명을 보여 줍니다.

```
GE-C003  (01)  Check digit validation failed for AI (01) value ''09506000134350''
```

> 그 메시지에서 겹쳐 나오는 따옴표는 이 애플리케이션이 아니라 엔진의 오류 카탈로그에서 온
> 것입니다.

### 기존 캡처 편집하기

캡처를 오른쪽 클릭 → **생성** 을 고르면 그 AI들이 편집기에 불러들여집니다. 값을 바꾸고 다시
생성하면 결과는 새로운 캡처로 추가되고, 원래 캡처는 그대로 남습니다.

## 보고서

선택한 캡처는 완전한 보고서로 그려집니다. 판정 배너, 이름표가 붙은 “테이프” 로 분해된 요소
문자열, 파싱 메타데이터, AI마다 하나씩인 해석 카드, 그리고 고치는 방법을 곁들인 오류와 경고가
포함됩니다.

**Digital Link** 인 경우, 각 AI 카드에는 구조적 역할 — **기본 키**, **키 한정자**, **데이터 속성**
— 도 URI에 나타나는 순서대로 색으로 구분되어 표시됩니다. 역할은 Digital Link에서만 표시됩니다.
평범한 요소 문자열에서 AI에는 설명할 URI 위치가 없기 때문입니다.

보고서는 선택한 언어와 테마를 따릅니다.

### 내보내기

| | |
|---|---|
| **보고서 저장 → HTML로…**(<kbd>⌘S</kbd>) | 화면에 있는 그대로 씁니다. 어떤 브라우저에서든 열리는 단독 완결 파일입니다 |
| **보고서 저장 → PDF로…**(<kbd>⌘P</kbd>) | 시스템 인쇄 대화 상자를 통해 보고서를 인쇄합니다. 거기서 PDF 대상을 고르십시오 |

PDF가 인쇄 대화 상자를 거치는 이유는 대상과 파일 이름을 그곳에서 고르기 때문입니다. macOS에서는
**PDF ▾ → PDF로 저장**, Windows에서는 **Microsoft Print to PDF**, Linux에서는 **파일로 인쇄** 를
선택하십시오. 페이지는 알맞게 나뉘고 글자는 선택 가능한 상태로 남습니다.

인쇄와 PDF 출력은 애플리케이션이 어두운 테마일 때에도 항상 밝은 색 조합을 사용하며, 색이 있는
AI 표시와 판정 배너를 그대로 유지합니다.

프린터도 PDF 대상도 설정되어 있지 않으면 애플리케이션이 그 사실을 알리고 HTML 내보내기를
안내합니다. HTML은 어떤 브라우저에서도 인쇄할 수 있습니다.

## 파싱 옵션

오른쪽 패널에는 엔진의 옵션이 모두 모여 있습니다. 무엇이든 바꾸면 **선택한 캡처가 즉시 다시
파싱되므로**, 이 패널은 다음 스캔에만 영향을 주는 것이 아니라 “이 설정이라면 이 입력은 어떻게
보일까” 를 물어보는 도구이기도 합니다.

| 옵션 | 값 |
|---|---|
| 구문 분석 모드 | `SYNTAX`, `CONTENT`, `DATA_CARRIER`, `INTERPRETATION` — 어디까지 깊이 분석할지 |
| 언어 | 35개 메시지 카탈로그 |
| 순서 | `LITTLE`(dd/mm/yyyy), `MIDDLE`(mm/dd/yyyy), `BIG`(yyyy/mm/dd) |
| 구분자 | `SLASH`, `HYPHEN`, `PERIOD` |
| 월 | `TWO_DIGIT`(12), `THREE_LETTER`(DEC) |
| 연도 | `FOUR_DIGIT`(2026), `TWO_DIGIT`(26) |
| "requires" 검사 건너뛰기 | 필수 동반 AI가 없어도 더 이상 거부하지 않습니다 (`GE-S005`) |
| "excludes" 검사 건너뛰기 | 표준이 금지하는 AI 조합도 더 이상 거부하지 않습니다 (`GE-S006`) |

패널 아래쪽의 *기본값으로 재설정* 은 엔진 자체의 기본값을 되돌립니다.

### 첫 실행

아직 저장된 것이 없을 때, 애플리케이션은 엔진의 기본값 대신 **사용자 컴퓨터의 지역 설정** 에서
설정을 가져옵니다.

- **언어** 는 시스템 로캘에서 오며, 해당 카탈로그가 없으면 영어로 되돌아갑니다.
- **날짜 옵션** 은 로캘의 짧은 날짜 형식에서 읽어 냅니다. 구성 요소의 순서, 구분자, 그리고 월과
  연도를 줄여 쓰는지 여부입니다.

> **참고.** 따라서 짧은 날짜를 두 자리 연도로 적는 로캘에서는 여기서도 두 자리 연도로 시작합니다.
> 시스템의 다른 부분과는 일치하지만, 네 자리인 엔진 기본값과는 다릅니다. 패널에서 바꾸면 그
> 선택이 유지됩니다.

## 언어

언어를 고르면 오류 메시지뿐 아니라 **애플리케이션 전체** — 메뉴, 버튼, 편집기, 옵션 패널, 상태
줄, 보고서 — 가 바뀝니다. 오른쪽에서 왼쪽으로 쓰는 언어에서는 창과 보고서가 뒤집힙니다.

35개 언어를 모두 사용할 수 있으며, 적용 범위는 두 층입니다.

| | 적용 범위 |
|---|---|
| 파싱 보고서와 엔진의 모든 오류 메시지 | **35개 언어 전부** |
| 애플리케이션 자체의 메뉴, 버튼, 이름표 | **35개 언어 전부** |

오른쪽에서 왼쪽으로 쓰는 언어 — 아랍어, 이집트 아랍어, 페르시아어, 우르두어 — 는 애플리케이션이
열리는 순간부터 창과 보고서를 뒤집습니다.

언어는 실행과 실행 사이에 기억됩니다. 한 번만 다른 언어로 열려면
[`--language`](#실행하기)를 참조하십시오.

몇 가지는 모든 언어에서 일부러 번역하지 않습니다. 원시 값 옆에 표시되는 짧은 항목 이름
(`format`, `position`, `raw`, `len` 등)은 낱말이 아니라 식별자이고, 예제 이름과 심볼 체계 이름은
GS1 및 업계 용어이며, 긴 표준 문단 하나는 어설픈 번역이 오히려 오해를 부르기 때문입니다.

## 무엇이 기억되는가

홈 디렉터리 안 `.gaia-desktop` 에 있는 두 파일입니다.

| 파일 | 내용 |
|---|---|
| `options.properties` | 모든 파싱 옵션, 테마, 옵션 패널의 열림 여부, 마지막으로 사용한 스캐너, 창을 닫을 때의 모드 |
| `captures.tsv` | 캡처 기록. 최신 항목이 먼저이며 최대 500건 |

옵션은 바꿀 때마다, 기록은 바뀔 때마다 기록됩니다. 둘 다 종료할 때 다시 기록됩니다.

둘 중 하나를 삭제하면 그 부분만 초기화되고 다른 것에는 영향이 없습니다. 손상된 기록 때문에
설정까지 잃지 않도록 둘을 따로 두었기 때문입니다. 직접 편집하다 망가진 파일도 치명적이지
않습니다. 설정은 항목마다 따로 기본값으로 되돌아가므로, 잘못된 한 줄은 그 한 줄만큼만 손해입니다.

기록은 파싱 결과가 아니라 입력을 저장합니다. 불러올 때 다시 파싱되므로, 복원된 캡처는 캡처 당시가
아니라 **지금** 적용 중인 옵션을 반영합니다.

## 문제 해결

| 증상 | 원인과 해결 |
|---|---|
| 애플리케이션이 시작되지 않거나 `NoClassDefFoundError` 가 표시됨 | `lib/` 디렉터리가 JAR 파일 옆에 있어야 합니다. 함께 두거나 단독 완결 배포본을 사용하십시오 |
| 시작할 때 콘솔에 *“Unsupported JavaFX configuration…”* | 예상된 무해한 메시지입니다. 툴킷이 자신이 어떻게 로드되었는지 알릴 뿐이며 애플리케이션은 정상 동작합니다 |
| 붙여넣은 구분자가 사라진 것처럼 보임 | 의도된 동작입니다. 눈에 보이는 `{GS}` 토큰으로 바뀌며 파서는 여전히 진짜 문자를 받습니다. [{GS} 토큰](#입력창과-gs-토큰) 참조 |
| *스캐너 연결* 버튼이 없음 | macOS나 Linux를 쓰고 계십니다. 그 환경에는 스캐너 드라이버가 없습니다. [스캔](#스캔) 참조 |
| 스캐너가 연결되지 않음 | 선택 목록의 논리 이름이 모델과 맞는지, 스캐너가 연결되어 있는지, 다른 프로그램이 점유하고 있지는 않은지 확인하십시오 |
| PDF 내보내기에서 대상이 없다고 표시됨 | 프린터나 PDF 대상이 설정되어 있지 않습니다. 하나 추가하거나 HTML로 내보낸 뒤 브라우저에서 인쇄하십시오 |
| 메뉴 항목에 `act.hri` 같은 것이 보임 | 이름표가 빠졌습니다. 알려 주십시오. 설정 문제가 아니라 빌드 단계의 결함입니다 |

## 제한 사항

- **스캔은 Windows 전용** 입니다. 드라이버가 그렇기 때문입니다.
- **PDF는 저장 대화 상자가 아니라 인쇄 대화 상자**를 거칩니다.
- **Digital Link 대상은 도메인과 경로 접두사만** 받습니다. 추가 질의 매개변수나 프래그먼트는
  지원하지 않습니다.
- **하나의 요소 문자열에서 같은 AI는 한 번만** 나타날 수 있습니다. 이는 애플리케이션의 제한이
  아니라 GS1의 규칙입니다.
